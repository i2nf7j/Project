## 1. 현재 단계와 범위

**2026-10-07 업무 기준 재검토:** 새로 전달된 08:30 일일 작업건수 입력·16:00 DELLIS 실적 대조·BNOC 정비통제담당·지휘관/참모 및 작전 관련 긴급 요청을 [업무 기준 보완안](development/operating-baseline-review-2026-10-07.md)에 정리했다. 08:30 입력 의미는 사용자가 아직 불명확하다고 답했으므로 확인 항목으로 유지한다. 16시 대조 수준은 사용자 답변에 따라 부서별 정비 완료 건수로 확인했다. 입력 방법·집계 기간/단위, 담당 직책의 권한과 요청 성격·긴급도 설계는 미확정이다. 아래 과거의 보고 제외를 새 요구에 대한 최종 결론으로 적용하지 않는다. 실제 DELLIS 이관·자동 연동은 도입하지 않는다. 작업건수 입력 주체는 정비부서로 정정했고, 조치결과는 완료 처리 시 직접 작성하는 의미로 확인했다. 완료 후 수정 권한이나 DELLIS 수치 재입력 의무를 추가하지 않는다.

요구사항 분석 후 UX 설계·기술 검토 단계의 기준 문서다. 문서 작성은 구현 완료를 의미하지 않는다. 2026-09-09 읽기 전용 파일 조사에서 src는 비어 있고 package.json과 Gradle 빌드 파일이 발견되지 않았다. 실행 가능한 제품이나 빌드 결과는 아직 없다.

목표는 3명이 2026-11-06까지 제출할 인터넷 환경의 웹 시연 체계다. 2026-09-09 개정에 따라 상위 메뉴는 대시보드·정보통신 운영·부대운영·정비관리로 구성한다. 독립된 부대별 권한, 가상 자료, 지정 스택을 유지한다. 별도 설치형 앱, 외부 군수체계 연동, 제품 AI 기능은 제외한다. 향후 인트라넷 운영과 이번 시연 배포를 구분한다.

지원 화면은 PC 최소 1280px와 전시기다. 모바일은 제외하고 날짜별 통합·기간별 정비 엑셀을 유지한다. 기존에 제외했던 16시 보고 관련 범위는 2026-10-07 전달된 실적 대조 업무와 구분하여 재검토한다. BNOC·관리자의 대리 접수는 확정 범위다. 병력 규칙은 2026-10-05 사용자 확인에 따라 §4의 현재 목업 기준으로 통일한다. 이번 정리는 실제 서버 구현 완료를 뜻하지 않는다.

아래 구현 순서는 우선순위 제안이며 기능 축소 합의가 아니다. 2026-09-16 요청에 따라 CPCON 대시보드 요약·상세 탭을 DB 연결 없이 우선 구현한다. 정적 단계 정의와 프런트엔드 시연 값을 사용하며, 관리자 또는 사이버(정보보호) 특기 직렬의 단계 수정을 목업에서 시연한다. 서버 권한 검사·영구 저장·다중 브라우저 동기화는 후속 연동 범위다.

CPCON 단계 설정은 역할표의 일반 운영상황 입력 권한과 별도로 판정한다. **관리자이거나 사이버(정보보호) 특기 직렬인 사용자**만 허용된 부대 범위에서 설정·변경할 수 있다. BNOC 역할만으로는 허용하지 않는다. 그 외 사용자는 기존 조회 권한 범위에서 읽기만 가능하다. 후속 연동 수용 기준은 허용 사용자의 변경 성공과 비허용 사용자의 직접 API 변경 요청 거부다.

‘기본’은 최소 권한 제안이다. 정비반의 공조 요청·수락은 확정했다. 일반 사용자의 병력 조회·다운로드는 제외하고 근무자(야간) 조회·내보내기는 허용한다. 정비사는 부대 전체 병력을 조회하며 병력 수정·확인은 BNOC·관리자만 수행한다. 그 밖의 지시사항 등 조회 범위는 해당 기능 명세를 따른다. 2026-10-06 확정: 첫 시연의 계정·소속·역할·조회 허용 범위는 관리자가 사전 등록한다. 회원가입, 사용자 계정·권한 신청 및 승인 절차는 첫 시연에서 제외한다. 소속·권한 변경이 필요하면 관리자에게 문의하며 사용자가 직접 수정하지 않는다.

## 4. 업무 흐름과 상태

### 첫 시연 계정 운영 (2026-10-06 확정)

- 관리자가 역할별 가상 계정과 소속·조회 허용 범위를 미리 준비한다. 일반 사용자·BNOC·정비부서·사이버 특기·관리자·상위 조회자의 기존 업무 권한은 그대로 적용한다.
- 실제 로그인·로그아웃과 서버의 역할·부대별 접근 검사는 첫 구현에 포함한다. 목업의 역할 선택 목록을 실제 인증으로 대체하지 않는다.
- 사용자 ID와 역할은 별개다. 본인 요청·개인 설정·알림 읽음·변경 이력은 실제 사용자 ID로 구분한다. 같은 역할의 두 계정과 다른 부대 계정으로 데이터 격리를 확인한다.
- 회원가입, 사용자 계정·권한 신청, 승인 대기·승인/반려 화면과 API는 첫 시연 범위에서 제외한다. 후속 도입 여부는 별도 결정한다.
- 사전 등록 자료와 재실행 가능한 초기 등록 절차는 첫 구현 산출물로 준비한다. 이번 확정은 계정 관리 화면이나 실제 로그인·DB 구현 완료를 의미하지 않는다.

### 정비

일반 사용자가 정비 요청에서 희망 부서를 선택할 수 있다. BNOC는 정비 접수에서 희망 부서 유무와 관계없이 접수·배정을 확정한다. 정비부서는 정비 진행에서 배정 작업을 확인하고 동일 화면의 목록·캘린더로 관리한다. 부서별 작업은 원격·출동 조치, 일반·긴급 우선순위, 일정과 진행상태를 가진다. 모든 관련 작업이 조치 완료되면 BNOC 확인 후 종결한다.

| 공조 | 대기 → 거절 / 철회 | 수신 부서 거절 / 요청 부서 철회, 사유·처리자·시각 기록 |

| 접수 | 조치 중 / 공조 처리 대기 → 종결 대기 | 관련 작업 전체 완료, 대기 공조 없음 |
| 접수 | 종결 대기 → 종결 | BNOC 확인 |

반려·취소 권한, 배정 전 선조치, 작업이 없는 접수의 처리, 협조 부서 추가 후 상태 계산은 상세 결정 대상이다. 정비사의 조치 완료 건수와 BNOC 종결 건수는 혼합하지 않는다.

### 병력 및 업로드

기준 인원 명단, 기간별 직접 지정 상태, 날짜별 근무 편성, 날짜별 병력 확인 기록을 구분한다. 2026-10-05 사용자 확정에 따라 현재 목업의 다음 규칙을 개발 기준으로 사용한다.

1. 조회 날짜에 직접 지정한 상태가 있으면 그 값을 사용한다. 휴가·출장뿐 아니라 직접 지정한 주간·오프·당직·야간 등에도 같은 우선순위를 적용한다. 겹친 기간은 마지막 적용이 우선이다.
2. 직접 지정 상태가 없으면 전날의 당직·야간을 확인해 자동 오프로 표시한다. 명단 ID로 연결한 근무 편성은 근무 시작일 다음 날을 기준으로 하고, 병력에 직접 지정한 당직·야간도 다음 날 자동 오프를 만든다. 명단 외 직접 입력 인원은 자동 연결하지 않는다.
3. 직접 지정 상태와 자동 오프 조건이 모두 없으면 기본 주간이다. 전날 상태 전체를 복사하지 않으며, 기간이 끝나면 해당 날짜의 자동 오프 조건을 다시 계산하고 없으면 주간이다. 명시적으로 저장된 미입력 값이 있더라도 입력 부재의 기본값으로 사용하지 않는다.
4. 날짜별 확인 완료는 상태 계산과 별개다. BNOC·관리자가 확인자·확인 시각을 남기며 기본 주간만으로 확인 완료가 되지 않는다. 미래 날짜는 편집할 수 있지만 확인 완료로 처리하지 않는다.
5. 기간 상태를 변경하면 해당 기간부터 종료 다음 날까지의 병력 확인을 해제한다. 근무 편성을 바꾸면 시작일 다음 날의 병력 확인을 해제한다. 인원 기본정보 수정은 기존 병력 확인 기록을 해제한다. 자동 오프는 변경된 원본으로 다시 계산한다.

BNOC·관리자의 직접 수정과 업로드 적용은 이 규칙을 공유한다. 업로드는 정상 행만 갱신하고 누락·오류 행의 기존 기간 상태·근무 편성 원본은 보존한다. 기존 값이 없는 행은 위 계산 규칙을 적용한다. 변경 이력과 행별 결과를 남기며 상세 처리는 §6.5~6.6을 따른다. 실제 업로드·서버 처리는 후속 구현 범위다.

### 야간 근무와 동기화

각 대대 BNOC가 자기 대대 근무표를 관리한다. 근무자 소속이 다른 부대여도 관리 대대 권한으로 등록하며 다른 부대의 원본 근무표를 수정하지 않는다. 통합 조회는 허용된 대대 자료를 취합한다. 병력과 근무 편성은 별도 원본으로 저장하되 명단에 연결한 당직·야간은 위 규칙에 따라 다음 날 병력의 자동 오프에 반영한다. 병력 상태 변경이 근무 편성을 역으로 수정하지 않는다. 자동 갱신 후에도 편집 중인 입력은 보존해야 한다.

### 6.2. 공조 요청·수락

- BNOC가 최초 접수 시 주관 부서 1곳을 지정한다. 추가 참여는 공조로 연결한다. 같은 대대의 정비반이 다른 정비반에 공조를 요청한다. 요청받은 정비반의 권한 있는 담당자가 직접 수락한다.
- 요청·수락 결과를 BNOC에도 알리고 현황에 반영한다. BNOC 사전 승인 대기 단계는 두지 않는다.
- 수락 전 요청은 작업 건수에 포함하지 않는다. 수락하면 같은 접수에 협조 부서 작업을 연결하여 1건 추가한다.
- 동일 요청을 동시에 수락하거나 재전송해도 협조 작업이 중복 생성되지 않도록 한다.
- 각 부서는 자기 작업을 수정·완료한다. 공조 수락 권한이 다른 부서의 작업 수정 권한을 의미하지 않는다.
- 최초 정비 요청의 BNOC 접수·배정과 공조의 수신 부서 직접 수락을 구분한다. 정비사의 최초 요청 승인 권한은 2026-09-09 개정으로 배정 작업 확인으로 바뀌었다. 긴급 선조치는 유지한다.

예: A반이 B반에 전원 점검을 요청하면 접수 1건·작업 1건이다. B반 수락 후 접수 1건·작업 2건이 되고 BNOC 화면에 표시된다. BNOC 승인 버튼을 누를 필요는 없다.

2026-10-05 확정: 수락 전 대기 공조는 수신 부서가 거절하거나 요청 부서가 철회한다. 두 처리 모두 사유가 필수이며 요청 사유와 별도로 처리 사유·처리자·시각을 보존한다. 거절·철회는 작업을 생성하지 않고 작업 집계에 포함하지 않는다. 이미 수락·거절·철회한 공조는 다시 처리할 수 없으며, 지원이 다시 필요하면 새 공조로 요청한다. BNOC·관리자의 강제 거절·철회 권한은 두지 않는다.

관련 작업이 모두 완료되어도 대기 공조가 남으면 접수는 ‘공조 처리 대기’다. 대기 공조를 모두 처리하고 관련 작업이 모두 완료되어야 ‘종결 대기’가 되며 BNOC가 최종 종결한다. 종결·취소된 접수의 공조는 수락·거절·철회할 수 없다. 요청·수신 부서와 BNOC·관리자는 처리 이력을 조회한다. 목업은 처리자 대신 시연 역할을 기록하며 실제 서버에서는 인증된 사용자 식별자를 저장한다.

### 6.3. 조치 완료·종결의 단순화

현재 흐름은 신청, 승인·배정, 작업 수행, 정비반 조치 완료, BNOC 종결이다. BNOC의 추가 조치 요청 버튼, 완료 작업 재개, 재완료 횟수·재개 유입 통계는 이번 범위에서 제외한다. 일부 부서만 완료한 경우에는 나머지 부서 작업이 끝날 때까지 종결 대기 조건을 충족하지 않는다.

예: 작업 3건 중 2건 완료이면 미완료 1건을 계속 관리한다. 3건 모두 완료한 뒤 BNOC가 종결한다. 별도의 반송·재작업 단계를 거치지 않는다.

새 장애는 기존 일반 고장 신청 기능으로 등록할 수 있다. 이전 접수 연결이나 종결 취소 전용 기능은 이번 결정으로 추가하지 않는다. 오입력 정정·작업 취소의 세부 권한은 별도 미정이며, 추가 조치 절차 제외를 기록 수정 전체 금지로 해석하지 않는다.

2026-10-06 확정: BNOC·관리자는 운영 일정 화면에서도 조치 결과를 입력해 연결 작업을 완료할 수 있다. 계획 내용·우회 방안과 조치 결과는 구분한다. 정비 진행과 운영 일정은 같은 작업 완료 처리를 사용해 완료일·확인 여부·작업 이력·조치 결과와 BNOC 완료 알림을 함께 반영한다. 완료된 일정의 재저장·새로고침으로 완료 이력이나 알림을 추가하지 않는다. 이미 완료한 작업의 결과 변경·재개·취소는 이 기능에서 허용하지 않으며 BNOC의 접수 최종 종결은 기존 조건에 따라 별도로 수행한다.

### 6.4. 기간별 통계와 엑셀 내보내기

16시는 완료 실적 대조의 기준이며 요청 접수 마감 시각이 아니다. 16시 이후 요청 등록을 막는 규칙은 두지 않고 실제 조치 시점은 별도의 근무·당직·긴급 대응 기준을 따른다. 현재 잠정 기간에서는 16시 이후 완료분을 다음 대조 기간에 포함하며, 접수 시각과 완료 시각을 혼합하지 않는다.

2026-10-07 잠정 대조 기간: DELLIS와의 부서별 완료 건수 대조는 사용자 답변 ‘2번 같기는 해. 일단은’에 따라 전일 16:00~당일 16:00(한국 표준시)을 가정한다. 확정 요구는 아니며 정확한 경계·휴일·누락 입력 처리는 추가 확인한다. 기존 날짜별·기간별 통계를 일괄 변경하지 않는다. 현재 목업의 날짜 단위 완료값으로는 이 시간 경계 집계를 검증할 수 없다. 상세는 [업무 기준 보완안](development/operating-baseline-review-2026-10-07.md)을 따른다.

2026-09-16 추가 요구: 정비 현황에서 조회 가능한 전체 부서 또는 개별 부서를 선택하고, 일간·주간·월간·직접 지정 기간을 함께 적용한다. 요약 수치·그래프·상세 목록의 부서와 기간은 일치해야 한다. 시작일이 종료일보다 늦으면 조회를 막고 수정 안내를 제공한다. 조회 결과가 없으면 0건과 빈 목록을 표시하며 진척도는 ‘—’다.

사용자 선택에 따라 그래프는 부서별 작업 건수를 기본으로 확정하고 태그별 분석은 추후 결정한다. 부서 비교는 관리대상 안의 완료·미완료를 표시하고, 기간 추이는 구간별 신규·완료 건수를 표시한다. 부서별 작업 수는 주관·공조를 구분한다. 후속 태그 분석은 접수 대표 태그 또는 작업별 업무 태그 중 집계 단위를 명시하고 각각 최대 1개 태그로 센다. 미선택은 `미지정`에 포함하며 공조 작업은 해당 공조 부서의 태그를 사용한다. 상세 미등록 수동 건수는 별도로 표시한다.

수용 기준: 같은 기간에서 부서를 바꾸면 해당 부서의 값만 표시되고, 같은 부서에서 기간을 바꾸면 해당 기간의 대상·완료·미완료와 상세 목록이 일치한다. 그래프의 막대·구간을 선택하면 동일한 부서·기간·지표 조건의 목록을 확인한다. 완료 추이는 실제 조치 완료 시각을 사용하며 예정일을 완료일로 대신 사용하지 않는다. 2026-09-16 통합 목업에 가상 배정·완료·상태 이력을 추가하여 부서·기간 필터와 그래프를 구현했다. 서버의 실제 이력 조회는 미구현이다.

기간별 관리대상은 기간 시작 시 미완료인 작업과 기간 중 새로 대상에 포함된 작업을 합쳐 같은 작업 ID를 한 번만 집계한다. 일별 대상 합계를 주간·월간 대상으로 사용하지 않는다. 기간 내 같은 부서 작업이 여러 날 이월되어도 한 번만 센다. 접수 건수와 부서별 작업 건수는 별도다.

완료는 관리대상 중 기준 시점에 조치 완료인 작업 수이며, BNOC 종결 수와 구분한다. 미완료는 유효 대상에서 완료를 뺀 값이고 보류도 미완료에 포함한다. 진척도는 완료/유효 대상이며 대상 0건은 ‘—’다. 취소는 기획서대로 대상에서 제외하되 취소·정정의 세부 규칙은 별도 결정한다.

예: 월요일 대상 10건 중 6건 완료. 화요일 4건 이월에 신규 2건을 추가하고 3건 완료. 화요일 현황은 대상 6건·완료 3건·미완료 3건·50%이고, 화요일 기준 주간은 대상 12건·완료 9건·미완료 3건·75%다. 일별 대상의 합인 16건으로 표시하지 않는다.

16시 보고 보관·스케줄러·보고 수정/복원은 기존 제외 결정이며, 2026-10-07부터 16시 DELLIS 실적 대조와 대조 기록의 필요성을 별도로 재검토한다. 기존 보고 기능 전체의 복원은 확정하지 않았다. 날짜별 통합 현황과 기간별 정비 현황은 조회 권한·적용 기간을 명시한 엑셀로 내보낸다. 현재 저장값인 명단·운영 상태는 과거 스냅샷으로 표현하지 않는다.

설계 기준: 시간대는 Asia/Seoul을 사용한다. 종료된 기간은 기간 말 상태, 진행 중인 기간은 현재 상태로 집계한다. 운영 일정에서 새로 생성한 계획정비는 등록·배정일부터 신규 작업에 포함하고 완료는 실제 조치 완료일을 사용한다. 기존 작업 연결은 작업을 추가 생성하지 않는다. 08:30 일일 작업건수 입력은 2026-10-07 요구 재검토 대상이며 대상 날짜·계획/실적/미완료 의미를 확인하기 전에는 별도 기록·자동 집계 규칙을 확정하지 않는다.

수동 건수는 등록 묶음과 이월 출처를 연결하여 매일 신규 건수로 다시 더하지 않는다. 신규·완료·취소·잔량을 분리하고 완료·취소 합이 대상을 넘지 않도록 검증한다. 개별 정보가 없는 수동 건수와 상세 작업 사이의 실제 중복을 자동으로 완전히 판별할 수 없으므로 입력 안내와 분리 표시가 필요하다. 전환·정정 규칙은 상세 설계에서 확정한다.

### 6.5. 포함 인원만 갱신

BNOC 소속 부대·선택 기준일에서 인원 식별번호로 대조하여 파일에 있는 정상 행만 입력·갱신한다. 파일에서 빠진 인원의 기간 상태·근무 편성 원본은 보존한다. 직접 지정 값이 없는 인원은 자동 오프 조건을 확인하고 없으면 기본 주간으로 표시하며 어제 값을 통째로 복사하지 않는다. 실제 변경이 반영된 날짜와 자동 오프 영향 날짜의 확인을 해제한다. 일일 현황 업로드로 기준 명단을 삭제하거나 소속을 바꾸지 않는다.

예: A=주간, B=휴가, C=출장인 상태에서 A=근무 오프, B=주간인 파일을 올리면 A·B만 바뀌고 C=출장은 유지된다. D에 직접 지정 값과 전날 당직·야간 조건이 모두 없으면 D는 기본 주간이다. E에 직접 지정 값은 없지만 전날 명단에 연결된 야간 근무가 있으면 E는 자동 오프다.

미리보기에는 신규·변경·동일·누락·오류를 구분하고 변경 전후 값을 보여준다. 빈 상태값은 삭제 명령으로 간주하지 않는다. 미리보기 후 다른 사용자가 수정한 행은 충돌로 구분하여 최신 값과 다시 비교한다.

야간 근무 업로드도 정상 행 우선 반영 원칙을 적용한다. 기존 근무 식별번호로 수정하고 누락 근무를 삭제하지 않는 방식을 설계 기본안으로 둔다. 신규 근무 재업로드의 중복 식별 방식은 API·업로드 양식 설계에서 명시한다.

### 6.6. 정상 행 우선 반영

- 검증·미리보기 후 적용 시 정상 행만 저장하고 오류 행의 기존 데이터는 유지한다.
- 처리 결과에 적용·변경 없음·검증 오류·충돌·저장 실패를 구분한다. 미적용 행은 행 번호와 이유를 제공하여 수정 후 재업로드할 수 있게 한다.
- 식별번호를 기준으로 재적용하므로 이미 반영된 정상 행이 다시 입력되어도 중복 인원·상태를 만들지 않는다.
- 같은 인원·기준일이 파일에 중복되면 해당 중복 행들을 모두 오류로 구분하고 무관한 정상 행을 처리한다. 먼저 나온 행을 임의로 선택하지 않는다.
- 행 검증 오류와 파일 전체 오류를 구분한다. 읽을 수 없는 파일, 필수 열 누락, 권한 없는 부대 대상 등은 파일 전체 처리를 중단하고 이유를 표시한다.
- 검증 오류 2행을 제외하는 것과 저장 중 장애로 일부만 반영되는 것은 다르다. 저장 결과를 확인해 실제 적용 행만 성공으로 표시하고 실패를 전체 성공으로 보고하지 않는다.

예: 30명 중 식별번호 오류가 2명이면 정상 28명을 먼저 반영하고 오류 2명은 기존 값을 유지한다. 수정한 2명만 다시 올려도 되고, 전체 파일을 다시 올려도 이미 같은 28명은 변경 없음으로 처리한다.

- 통계: 일·주간 예시 일치, 이월 중복 없음, 날짜별·기간별 엑셀의 필터·권한 일치. 16시 보고 기능 없음.

- 업로드: 포함 정상 행만 변경, 누락·오류 행의 원본 보존, 기존 값이 없으면 직접 지정 > 자동 오프 > 기본 주간 규칙 적용.
- 부분 반영: 정상 28명 성공·오류 2명 미적용 표시, 오류 수정 재업로드 시 중복 없음, 읽을 수 없는 파일은 전체 오류.

위는 구현 후 확인할 기준이며 실행한 테스트 결과가 아니다.

### 역할별 대시보드와 오른쪽 패널

최신 사용자 방향을 반영하여 공통 레이아웃(로고·왼쪽 메뉴·가운데 본문·오른쪽 패널) 안에서 역할별 홈을 제공한다. 동일한 정비 현황 화면에 숫자만 바꾸는 방식으로 제한하지 않는다. 오른쪽에는 지시사항과 해당 역할의 알림을 배치하며, BNOC 접수 대기 확인을 포함한다.

세부 배치 제안: BNOC는 운영현황·정비 캘린더·오늘 근무·정비 수치, 정비부서는 자기 부서 작업·일정·근무, 일반 사용자는 정비 요청 바로가기·본인 요청 목록·본인 일정·관련 근무 안내, 상위 조회자는 허용 부대의 읽기 전용 요약을 제공한다. 공통 대시보드는 메뉴의 첫 항목이며 일반 사용자가 본인 요청 화면을 첫 화면으로 사용한다는 이전 제안은 개인 홈의 요청 바로가기로 대체한다.

오른쪽 패널의 업무 목록은 BNOC 접수·종결 대기, 정비부서 미확인 배정·공조 수신, 일반 사용자 본인 처리 변경을 기본 제안으로 한다. 지시사항은 게시 대상 권한을 따르고 일반 사용자에게 내부 지시를 자동 공개하지 않는다. 부서 작업 알림은 개인별 알림 읽음과 별개다.

한 패널에 모든 항목을 쌓지 않고 짧은 미리보기와 전체 보기를 제공한다. BNOC는 처리 대기를 위에, 지시사항을 아래에 두는 구성을 제안한다. 지시사항 팝업을 기본으로 중복 표시하지 않는다. 미처리 건수와 안 읽은 알림 수를 같은 숫자로 취급하지 않는다.

화면 구현은 아직 시작하지 않았다. BNOC·일반 사용자 두 역할의 시안을 먼저 비교하고 정비부서·조회자로 확장한다. 특기별 운영체계 첫 표시와 일반 사용자 근무 정보 범위는 상세 설계 제안이다. 날씨 연동은 2026-09-16 요청에 따라 내수읍 기준 Open-Meteo 조회로 확정했다. 날짜는 목업에서 기기 시간 기준 한국 표준시를 표시하며, 운영 서버의 NTP 동기화·시각 API는 후속 연동한다.

| 요청 부서 | 일반 사용자는 계정 소속으로 입력. BNOC·관리자는 허용된 부대 범위에서 대리 접수하며 실제 요청 부서와 접수 계정을 분리 |
| 요청 유형 | 점검 / 증설 / 설치 / 이전 / 불용 / 기타 중 하나 필수 선택. 업무 태그와 별도 |
| 요청 대상 | 짧은 자유 입력 필수. 부서마다 다른 장비·업무 대상 입력 가능 |
| 수량 | 선택 입력. 양의 정수와 단위로 구성하며 입력한 경우에만 제목에 포함. 단위 기본 대, 대상별 변경 가능을 제안 |
| 요청 내용 | 증상·사유·범위 등을 자유롭게 작성. 제목 생성에 본문 분석을 사용하지 않음 |
| 제목 | `[요청 부서] 요청 대상 [수량·단위] 요청 유형 요청`. 수량 미입력 시 생략. 대리 접수는 입력한 요청 부서의 앞뒤 공백을 제거하고, 일반 사용자는 계정 소속 부서를 사용한다. 최초 표시·입력 변경·화면 재표시의 미리보기와 저장·조회·엑셀 제목에 같은 부서 기준을 적용한다. 요청 부서가 비면 입력 안내를 표시한다. 제출 시 서버에서도 같은 기준으로 생성 |
| 태그 | 희망 부서의 목록에서 최대 1개 선택, 미선택 허용·미지정 집계. BNOC가 확정 주관 부서에 맞춰 접수 대표 태그 확인 |
| 후보 추천 | 키워드·동의어 기반 후보 표시. ‘모니터’는 모니터, ‘PC·포맷’은 PC, ‘랜선’은 네트워크 후보. 자동 확정·부서 자동 배정으로 연결하지 않음 |
| 분류 범위 | 부서별 장비·업무에 맞는 목록 관리. 주관 작업의 최초 태그는 접수 대표 태그를 반영하고 공조 작업은 해당 부서의 태그를 별도로 선택. 실제 목록은 추후 작성 |
| 참여 구분 | 업무 태그와 별도인 주관 / 공조. 최초 주관 작업과 공조 수락으로 생성된 작업에 각각 자동 부여 |
| 알림 확인 | 부서 구성원이 작업 알림 조회. 한 사람이 알림을 읽었다고 모두의 읽음이나 작업 확인을 자동 변경하지 않음. 실제 작업 확인 주체·시각 기록 |

예: 가상 계정의 요청 부서가 ‘보급대대 유류통제반’, 대상이 ‘모니터’, 수량이 2대, 유형이 증설이면 제목은 ‘[보급대대 유류통제반] 모니터 2대 증설 요청’이다. 상세 내용이 구어체여도 제목에는 반영하지 않는다. 사용자가 태그를 선택하지 않으면 미지정 상태로 BNOC에 접수한다. 요청 1건·단일 부서 작업 1건은 그대로다.

키워드 추천은 기술적으로 가능하지만 ‘PC는 정상이고 전화기만 고장’ 같은 문장의 의미를 단순 단어 포함만으로 정확히 판단하지 못한다. 시연의 기본 기능은 수동 선택·BNOC 분류로 완성하고 추천은 그 위에 추가하는 방향을 권장한다. UI에서 추천과 확정 태그를 구분한다. 기획용 제목 생성에는 AI 요약이 필요하지 않다.

### 7.0. 후속 업무 질문 답변 — 확정 기록

이 절은 메뉴 개정 후 받은 다섯 질문의 답변과 사용자 예시를 기록한다. 앞선 기본안을 아래 내용으로 보완한다.

| 항목 | 확정 내용 |
|---|---|
| 요청 단위 | 개인이 작성한 게시글·요청서 1개는 요청 1건. 한 부서가 10대 처리해도 작업 1건. 선택 수량 입력란과 추가 메모로 수량·범위를 기록하고 개별 장비별 완료 관리는 도입하지 않는다. 여러 부서 참여 시 기존 부서별 작업 1건 기준 유지 |
| 작업 확인·상태 | 확인과 시작은 별개. 작업 예정·작업 중·보류·완료를 사용하며 애매하거나 대기할 때 보류 사유 기록 |
| 잘못된 배정 | 정비부서가 사유와 함께 BNOC에 재배정 요청, BNOC가 확정. 공조 추가와 구분 |
| 다른 부서 조회 | 정비부서 대시보드는 자기 부서 기본. 정비 현황에서 같은 대대 전체 부서의 관리대상·완료·미완료·진척도를 비교표로 조회한다. 상세 작업·조치내용·수정 및 엑셀 내역은 자기 부서 권한 유지. 병력·운영상황·지시사항 권한은 별도 |
| 월간 실적 | 지난달 접수하고 이번 달 완료한 작업은 이번 달 완료 실적에 포함. 이월·신규 배정·완료·잔량 함께 표시. 대시보드 현재 잔량과 정비 현황 선택 기간 실적 구분 |
| 담당 업무 예시 | 네트워크체계팀: 랜선 고장, 모니터 정비 요청, PC 포맷. 사용자 제공 분류를 업무 안내 예시에 사용 |
| 병력 배치 | 부서별 섹션·블록 유지, 각 블록 안 반원을 계급순으로 한 행씩 세로 나열. 상태는 직접 지정 > 자동 오프 > 기본 주간 순서로 표시하고 날짜별 확인 전/완료를 별도 표시 |
| 근무자(야간) | 통신일직·작통일직·생활관 근무자 등 구역·직책별로 당직 사관의 계급·성명·전화번호 표시. 대대별 BNOC 등록·취합 유지 |
| 표시 환경 | 약 75인치 TV, 주 사용 브라우저 Edge. 픽셀 해상도·배율·시청 거리·Edge 버전은 미확인 |

추가 메모는 요청 작성 및 작업 상세에 표시하는 단순 텍스트로 설계한다. 예: ‘모니터 10대, 가상 교육장 대상’. 장비별 작업을 자동 생성하지 않는다. 최초 요청 메모와 정비사의 조치내역은 구분한다.

월간 사례: 지난달 미완료 4건을 이월하고 이번 달 신규 2건을 배정하여 이월 중 3건을 완료했다면 이번 달 대상 6건·완료 3건·잔량 3건이다. 기간 내 고유 작업 기준과 기간별 엑셀을 유지한다. 다른 부서로 재배정된 작업의 부서별 실적 귀속은 상세 규칙 결정 대상이며 작업을 복제해 전체 건수를 늘리지 않는다.

병력 표시명 ‘주간’은 기존 ‘주간 근무’, ‘오프’는 기존 ‘근무 오프’와 같은 의미로 통일한다. 업로드 값 대응도 양식에서 명시한다. 계급·성명·전화번호는 기존 가상 자료 원칙에 따라 시연용 가칭과 가상 번호를 사용한다.

현재 업무 흐름·화면 검토를 먼저 보강한다. 물리 DB·API 확정은 대표 시나리오와 입력항목 검토 후 진행한다. 남은 자료는 평가표·필수 시연 항목과 실제 TV 출력 해상도이며 지금 답이 없어도 화면 시나리오 정리는 가능하다.

### 7.1. 2026-09-09 메뉴 개정 반영

사용자 확정 구조는 다음과 같다. 기존의 상위 두 탭 및 정비사의 일반 접수 승인 규칙을 대체한다.

```text
대시보드
정보통신 운영
 ├ 정보통신 운영현황
 └ 정보통신 상황
    ├ CPCON
    └ GPS 전파교란 위기경보단계
부대운영
 ├ 병력 현황
 ├ 근무자(야간)
 └ 지시사항
정비관리
 ├ 정비 안내·연락처 — 부서별 담당 업무·증상·복수 내선
 ├ 정비 요청  — 일반 사용자 신청·본인 내역
 ├ 정비 접수  — BNOC 접수·부서 배정·최종 종결
 ├ 정비 진행  — 부서 작업 확인·진행·완료·공조·일정 통합
 └ 정비 현황  — 월간·날짜·기간별 부서 실적
```

업무 편의 제안은 BNOC의 부대 전체와 정비부서의 자기 부서를 대시보드·정비 현황의 기본 범위로 사용하는 것이다. 대시보드 카드·그래프를 누르면 동일 부대·부서·기간·상태의 목록으로 이동한다. 전체 구조의 첫 메뉴는 대시보드지만 역할별 접근 범위는 서버에서 제한한다. 일반 사용자의 대시보드는 본인 요청 요약을 기본 제안으로 두며 부대 운영정보 권한을 자동 확대하지 않는다.

‘정비 현황’의 부서별 접수는 ‘배정 작업’으로 표시하는 것을 권장한다. 요청 접수 ID와 부서 작업 ID를 섞지 않는다. 상세 작업과 수동 건수는 출처를 분리한다. 기간 중 배정 유입 건수와 전일·전월 이월을 포함한 관리대상 수도 구분한다. 현재 작업 중과 전체 미완료를 같은 ‘진행 중’ 이름으로 혼용하지 않는다.

2026-10-05 사용자 선택: 정비사의 타 부서 요약은 한 부서씩 전환하는 방식 대신 비교표로 제공한다. 정비 현황의 적용 기간을 공유하고 부서 필터와 관계없이 같은 대대 전체 부서를 나열한다. 자기 부서는 ‘내 부서’로 표시하며 대상 0건의 진척도는 ‘—’다. 타 부서 행에는 작업 상세 링크를 두지 않는다. 비교용 응답은 부서 식별자·관리대상·완료·미완료·진척도만 포함하고 작업 ID·제목·조치내용을 포함하지 않는다. 아래 상세·추이와 기존 엑셀 내역은 자기 부서 기준을 유지한다. BNOC·관리자 및 상위 조회자의 기존 화면은 유지한다.

권장 카드: BNOC는 미배정 요청·미확인 배정·작업 중·보류·조치 완료·종결 대기, 정비부서는 자기 부서 미확인·작업 중·보류·완료·공조 수신·오늘 일정이다. 미확인은 확인 여부, 작업 예정/중/보류/완료는 작업 상태, 종결 대기는 접수 상태이므로 카드 전체를 합산한 총건수를 만들지 않는다. 그래프는 같은 단위인 작업상태별 분포만 비교한다.

### 7.2. 후속 단계

1. 요구사항 분석: 이 문서를 기준으로 영향이 큰 미정 사항을 구체화한다.
2. UX·기술 검토: 역할별 흐름·핵심 와이어프레임과 지정 스택 실행 가능성을 함께 검토한다.
3. UI·구현 명세: 디자인 규칙과 데이터·API 계약을 맞추고 한 사용자 흐름의 수용 기준을 확정한다.
4. 첫 구현: 시연 로그인, 미지정 신청, BNOC 배정, 정비사 완료, BNOC 종결, 두 화면 자동 갱신을 연결한다.
5. 기능 확장: 병력·업로드·야간 근무, 운영상태·상황·지시, 집계·캘린더·전시기 기능을 순차 완성한다.
6. 통합 검증: 권한 분리, 오류·동시 처리·재연결, 시연 순서와 배포 절차를 검증한다.

11월 6일은 고정 제출 목표다. 내부 목표는 10월 말 기능 완료 후 남은 기간을 결함 수정·시연 준비에 사용하는 것으로 제안한다. 주별 일정과 사람별 배정은 가용 시간 및 기술 검토 없이 확정하지 않는다.

Q-01~Q-05와 2026-09-09 메뉴 개정을 반영하고 UX·기술 문서 검토를 완료했다. 산출물은 [UX 명세](design/ux-spec.md), [기술 검토](development/technical-plan.md), [Planner 조율 기록](design-development-review.md)이다. 다음 단계는 대표 업무 시나리오와 화면 입력항목 검토다. 물리 DB·API 확정은 이후 진행한다. 제품 코드는 미구현이며 빌드·화면·DB·동기화 실행 검증은 아직 수행하지 않았다. 남은 세부 결정은 해당 기능의 상세 설계에서 다룬다.

## 날짜·날씨 수용 기준 (2026-09-16)

- 이번 시연의 완료 기준은 인터넷 날씨 API 연동이다. 실제 인트라넷 운영의 날씨 공급원은 국방 기상체계로 정하며, 해당 체계 연동은 별도 운영 전환 범위다.
- BNOC·정비사 목업에서 제17전투비행단의 소재 지역(청주시 청원구 내수읍) 날씨를 조회하고 기온·날씨 상태·자료 기준 시각·출처를 표시한다.
- DB 없이 최초 조회, 10분 주기 갱신, 수동 재시도를 제공한다. 통신 오류 시 실패 상태와 이전 자료 여부를 구분한다.
- 현재 날짜·요일·시각은 기기 시간 기준 한국 표준시로 갱신하며, 다른 기기 시간대에서도 한국 날짜의 자정 전환이 맞아야 한다. 기존 업무 시연 기준일은 별도 유지한다.
- 서버 구축 후 OS 기본 NTP 동기화와 서버 시각 API를 검증한다. 현재 목업을 NTP 연동 완료로 간주하지 않는다.

## 부서 안내·업무 태그·참여 구분 수용 기준 (2026-09-16)

- 안내는 부서명부터 시작하여 담당 업무·장비, 대표 증상, 용도별 복수 내선을 표시한다. 접수 중 안내를 열어도 입력 내용이 유지되고 부서 선택은 희망 부서에 반영된다.
- BNOC의 최초 배정은 주관 부서 1곳이다. 공조 수락 전에는 작업이 늘지 않고, 수락 후 공조 작업 1건이 추가된다. 단순 공유는 작업 생성·집계에서 제외한다.
- 부서 변경 시 새 부서에 속하지 않는 태그를 그대로 저장하지 않는다. 다시 선택하지 않으면 미지정으로 처리한다. 공조 작업 태그 수정은 접수 대표 태그와 주관 작업 태그에 영향을 주지 않는다.
- 예: 접수 대표 태그 PC, 주관 작업 PC, 공조 작업 태그 미선택이면 접수 1건·작업 2건이다. 작업 분류는 PC 1건·미지정 1건이고 참여 구분은 주관 1건·공조 1건이다. 이는 같은 두 작업을 다른 기준으로 분류한 값이므로 서로 더하지 않는다.
- 부서별 그래프는 기본 범위로 유지하고 태그별 그래프는 후속 구현한다. 통합 목업에서 안내·태그·주관·공조 흐름을 구현했다. 실제 서버·권한·저장은 미구현이다.

## 요청 제목 생성 수용 기준 (2026-09-16)

- 여섯 요청 유형을 모두 동일한 제목 규칙에 적용한다. 신청자의 요청 부서·요청 대상·요청 유형을 사용하며, 희망 부서·주관 부서·업무 태그 변경만으로 제목을 바꾸지 않는다.
- 모니터·증설·2대 입력 시 `[A부서] 모니터 2대 증설 요청`, 수량 제거 시 `[A부서] 모니터 증설 요청`으로 즉시 미리보기를 갱신한다. 수량의 단위만 제목에 남기지 않는다.
- 수량 입력 시 0·음수·소수와 단위 누락을 허용하지 않는다. 수량이 없는 요청은 제출할 수 있다. 요청 대상의 앞뒤 공백을 제거하고 공백만 입력하면 제출을 막는다.
- 본문에 ‘모니터 2대 증설해주세요~~’를 입력해도 제목은 구조화된 입력값만 사용한다. 수량 미입력 상태에서 본문 숫자를 자동 추출하지 않는다.
- 장비 수량 2대 또는 10대여도 요청 1건·단일 부서 작업 1건을 유지한다. 통합 목업에서 선택 수량을 포함한 제목 생성을 구현하고 브라우저에서 확인했다.

## 통합 목업 진행 현황 (2026-09-16)

[통합 목업](design/mockup.html)과 [사용·검증 안내](design/mockup/README.md)에 최신 요구사항을 반영했다. CPCON, 안내·연락처, 자동 제목, 부서별 태그, 주관·공조 처리, 부서·기간별 통계를 로컬 메모리에서 시연한다. 앞선 제품 코드·서버 미구현 기록과 구분하며, 실제 인증·DB·동기화·보고 원본 생성 완료를 의미하지 않는다.

## 상위 조회자 수용 기준 (2026-09-25)

- 상위 조회자 계정으로 전환하면 전체 3개 비행단 비교에서 시작한다. 비행단명 선택 또는 선택 필터 적용으로 해당 비행단만 조회한다.
- 비행단·기간 조건은 대시보드·정비 현황·정보통신 운영현황 간 이동 시 유지한다. 다른 계정에서 상위 조회자로 다시 전환하면 전체 비교와 기본 기간으로 시작한다.
- 부서별 합계는 선택 비행단의 합계와 일치하고 전체 완료율은 완료 총합/대상 총합이다. 기간 이월은 중복 집계하지 않으며 대상 0건의 완료율은 —다.
- 운영상태는 표시된 시점의 더미 스냅샷이다. 정비 기간을 변경해도 이를 과거 운영상태로 표현하지 않는다.
- 개별 요청·작업 상세와 수정 조작은 노출하지 않는다. 기존 BNOC·정비사 목업 데이터와 별도로 구성된 독립 집계 시연 자료다. 실제 부대 접근 권한은 서버 구현 범위다.
