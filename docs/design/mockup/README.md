## 2026-10-01 운영 흐름 개선

- 근무 구분은 당직·야간·주간입니다. 명단에서 연결한 당직·야간 근무자는 시작일 다음 날 병력 현황에 자동 오프로 표시됩니다. 병력 상태를 당직·야간으로 직접 지정한 경우도 다음 날 오프가 적용됩니다. 직접 지정한 휴가·출장 등 상태가 자동 오프보다 우선하며, 편성을 수정하면 자동 오프도 갱신됩니다. 명단 외 직접 입력 인원은 자동 연결하지 않습니다.

- 병력은 조회 날짜별로 기본 주간에서 시작합니다. 예외 상태에 시작일·종료일을 지정하며, 겹친 기간은 마지막 적용이 우선합니다. 기간 종료 후에는 자동 오프 조건을 다시 계산하고 해당하지 않으면 기본 주간으로 표시됩니다. 이 규칙은 2026-10-05 사용자 확인으로 개발 기준에 반영했습니다. [상세 기준](../../product.md#4-업무-흐름과-상태).
- BNOC·관리자가 날짜별 현황을 확인하면 확인자·확인 시각을 기록합니다. 해당 날짜의 상태를 바꾸면 확인 완료가 해제됩니다. 시연 기준일 이후는 미리 편집할 수 있지만 확인 완료는 할 수 없습니다. 기본 인원 정보를 수정하면 기존 확인 기록을 해제합니다.
- 직전 일괄 변경은 이후 병력 수정·확인이 없을 때 되돌릴 수 있습니다. 검색 결과 밖의 인원은 전체 선택에 포함하지 않습니다.
- 근무 편성은 날짜별 저장, 이전 편성 복사, 명단 검색·선택, 계급·성명·소속 자동 입력을 지원합니다. 명단 외 인원은 직접 입력하고, 동일 인원의 중복 배정은 거부합니다. 대시보드에는 업무 시연 기준일의 편성을 표시합니다.
- 수정 중 다른 메뉴·역할·조회 날짜로 이동하거나 창을 닫을 때 미저장 변경이 있을 경우에만 안내합니다. 저장 또는 취소 후에는 안내하지 않습니다.
- BNOC·관리자 대시보드 상단에 접수 대기·보류·종결 대기·병력 확인을 배치하고 해당 목록으로 연결합니다. 날씨·현재 시각은 접이식 보조 영역이며 업무 시연 날짜와 구분합니다. 오래된 운영현황은 갱신 확인 필요로 표시합니다.
- 장비 관리를 같은 메뉴로 통합했습니다. 현재 지원 범위는 PC 최소 1280px와 전시기이며 모바일은 제외합니다. 16시 보고 원본 생성과 준비 중 버튼은 2026-10-03 결정으로 제외했습니다.
- 업무·병력·근무 자료는 localStorage, 장비 자료·첨부파일은 IndexedDB에 저장합니다. 저장 실패는 화면에 알립니다. 같은 브라우저·동일 파일 경로(또는 동일 웹 출처)에서 재사용하며 서버 저장·다른 브라우저 동기화는 제공하지 않습니다. 설정의 **시연 데이터 초기화**로 이 목업의 저장 데이터만 지울 수 있습니다.
- 테스트: node --test tests/operations.test.cjs, node tests/operations.browser.cjs. 기간 경계·겹침·확인 해제·되돌리기·권한·명단 연결·이탈 방지·새로고침 보존·장비 파일 저장/다운로드·기존 경로 이동·초기화를 검증합니다.

## 권장 시연 순서

1. 상단 **시연 계정 → 일반 사용자**에서 정비 요청을 작성합니다. `모니터 / 2대 / 증설`을 입력해 자동 제목을 확인하고 등록합니다.
2. **BNOC**로 전환해 정비 접수에서 요청을 열고 주관 부서와 대표 태그를 지정합니다.
3. 담당 **정비사** 역할로 전환해 정비 진행에서 작업을 확인하고 공조를 요청합니다.
4. 공조받은 부서 역할로 전환해 공조 업무 태그를 선택하고 수락합니다. 수락 전에는 수신 부서가 거절하거나 요청 부서가 철회할 수 있으며 사유가 필수입니다. 정비 진행의 공조 처리 이력에서 사유·처리 역할·시각을 확인합니다. 모든 작업 완료와 대기 공조 처리가 끝난 뒤 BNOC가 종결합니다.

운영 일정에서도 BNOC·관리자가 상태를 ‘완료’로 선택하고 별도 조치 결과를 입력하면 연결 작업 완료·이력·BNOC 알림을 반영합니다(2026-10-06 확정). 정비 내용·우회 방안은 유지하고, 완료 결과는 읽기 전용입니다. 완료 일정의 재저장·새로고침은 알림을 추가하지 않습니다. `tests/operation-completion.browser.cjs`에서 두 진입점의 필수 결과·권한·새/기존 작업 연결·완료 이력·알림 중복 방지와 실패 시 원본 보존을 검증합니다.

2026-10-06 확정: 첫 시연 계정은 관리자가 사전 등록합니다. 사용자 회원가입·계정/권한 신청·승인 화면은 첫 시연에서 제외하고 개인 설정에 관리자 문의 안내를 표시합니다. 이 목업의 역할 전환은 가상 시연이며 실제 계정 등록·로그인·서버 권한 검증은 후속 구현 대상입니다.
5. 정비 현황에서 부서·기간을 바꾸거나 막대·추이 구간을 눌러 목록을 확인합니다. CPCON은 관리자·사이버 특기와 BNOC 역할의 설정 권한 차이를 확인합니다.

업무 시연 기준일은 **2026-09-16**입니다. 작업 처리일도 이 날짜로 기록하며 실제 기기 시각·날씨와 구분합니다. 재배정 이력이 있는 작업의 부서별 통계는 조회 종료 시점의 담당 부서 기준입니다. 실제 실적 귀속 규칙 확정 전 목업 기준이며, 신규는 배정일·완료는 조치 완료일로 집계합니다.

**저장한 변경사항은 새로고침 후에도 유지됩니다. 설정에서 시연 데이터를 초기화할 수 있습니다.** 역할 선택은 가상 권한 표현이며 실제 로그인·서버 권한·DB·브라우저 간 동기화는 미구현입니다. 태그별 그래프, 수동 건수 입력, 16시 보고 원본 생성, 별도 공유 기능은 미구현입니다. GPS는 고정 시연 자료를 표시합니다. 장비 운영은 통합 메뉴에서 제공합니다.

좌측 **정비관리 → 장비 운영**에서 아래 두 탭을 검토할 수 있습니다.

- **장비 목록**: 순번, 부서, 망 종류(국방망·전장망·센서망·LTE망·VoIP망·기타), 장비명, 사업명, 사업년도. 부서·망 필터, 장비명·사업명 검색, 장비 등록·수정을 제공합니다. 순번은 필터 결과의 표시 순서이며 장비 식별자는 별도로 유지합니다.
- **정보보호 프로그램**: 같은 장비 목록에 백신 버전, 설치현황(설치 완료·미설치·설치 불가·확인 필요), 설치 불가 사유, 비고, 업체 공문을 연결합니다. 설치 완료 시 버전, 설치 불가 시 사유는 필수입니다. 공문 확보 전 기록도 가능하며 ‘공문 미첨부’로 구분합니다.
- 공문은 PDF·PNG·JPEG·HWP·HWPX·DOC·DOCX를 여러 개 첨부할 수 있습니다. 파일당 최대 10MB이며 하나라도 검증에 실패하면 전체 저장을 중단합니다. 기존 첨부를 유지하면서 추가할 수 있고 파일명을 눌러 다운로드합니다.
- 첨부·기존 공문 연결 시 적용 범위를 이 장비만 / 같은 사업의 동일 장비명 / 같은 사업 전체로 선택하고, 관리번호·부서·망을 보며 대상 체크박스를 조정합니다. 공문 원본 한 개를 선택된 장비 ID에 연결하며 설치현황·버전·사유는 편집 중인 장비에만 반영합니다.
- 파일별 연결 해제는 현재 장비에만 적용됩니다. 같은 사업의 기존 공문은 재업로드 없이 재연결할 수 있습니다. 신규 장비에는 자동 적용하지 않습니다. 사업명·년도는 후보 조회에만 사용하고 실제 연결은 고정 장비 ID로 보관합니다. 실제 서비스에서는 별도 사업 ID와 장비 모델 ID로 분리해야 합니다.
- 세 번째 하위 탭은 용도 미정으로 화면에 추가하지 않았습니다.

각 장비는 1대당 1건으로 등록하며, 새 장비의 정보보호 현황은 ‘확인 필요’에서 시작합니다. 부서 선택은 가상대대 A의 예시 부서 3개로 제한됩니다.

날씨는 제17전투비행단 소재 지역인 청주시 청원구 내수읍의 대표 좌표를 Open-Meteo에 전달해 조회한다. 기온·날씨 상태·자료 기준 시각과 출처를 표시하며 10분 자동 갱신과 수동 재시도를 지원한다. 인터넷 연결 실패 시 확인 불가 또는 이전 자료임을 표시한다. API 응답은 예보 모델 자료다.

`node --test tests/environment.test.cjs`로 한국 날짜 전환·날씨 응답·통신 실패·오래된 자료 처리를 검증한다.

2026-09-16 검증: 실제 날씨 API HTTP 200 응답과 CORS 허용 헤더를 확인했다. 날짜·날씨 테스트 5건 및 기존 장비 테스트 10건이 통과했다. 실제 브라우저 렌더링은 미검증이다. 로컬 PATH에 Node.js가 없어 임시 폴더의 Node.js 22.14.0으로 테스트했다.

### 최신 운영현황 사용법
전체 체계 요약 → 구성 관리의 왼쪽 트리 선택 → 오른쪽 상세를 사용한다. 장비명·관리번호 검색은 해당 경로를 펼친다. 선택 항목에서 정비를 바로 등록하거나 정비 일정 탭에서 날짜를 고르고 등록한다. 이동 버튼은 다른 체계까지 선택하는 목적지 창을 연다.
삭제는 이름 입력 후 처리한다. 기록이 있으면 운영 종료로 보존하고 '운영 종료 포함'에서 조회한다. 예정 정비와 하위 구성은 먼저 정리한다. 대시보드 업무 안내는 지휘서신·지시사항과 분리했다. 상위 조회자는 비행단을 선택하면 독립 시연 자료의 장비·정비 상세를 읽기 전용으로 볼 수 있다.


### 엑셀 내보내기
대시보드·병력 현황·근무자(야간)·운영현황 상단에서 기준일을 선택해 일일 현황 통합 다운로드를 실행한다. 병력 현황/근무자(야간)의 조회 기준일은 내보내기 기본 날짜에 반영된다. 병력, 근무자 야간, 운영현황, 정비 예정 영향을 각각 별도 시트로 담는다. 정비 조회 가능 계정은 시연 기준일까지의 당일 정비 요약/내역도 포함한다. 상위 조회자는 허용 비행단 운영자료 2개 시트만 내보낸다.
정비 현황에서는 조회 버튼으로 적용한 시작일~종료일·부서/비행단 범위를 별도 파일로 받는다. 그래프 세부 선택은 적용하지 않으며 파일에 이 기준을 명시한다. 검색 결과가 아닌 조회 허용 전체 명단을 내보내며 편집 중 자료는 먼저 저장/취소해야 한다.
운영 상태·구성·병력 명단 정보는 현재 저장값이다. 과거 운영상태 스냅샷이 아님을 파일에 표시한다. 근무 미등록일에는 임의 편성을 생성하지 않는다. XLSX는 브라우저에서 생성되며 네트워크 업로드·CDN 연결이 없다.
검증: tests/export.browser.cjs. XLSX를 독립 리더로 읽고 날짜/시트/고정행을 확인했으며 시트 렌더링을 검토했다. MS Excel 데스크톱 직접 실행 검증은 수행하지 않았다.


최신 범위 조정: 일반 사용자는 병력 조회·엑셀 내보내기에서 제외되며 근무자(야간)는 조회 가능하다. 메뉴명은 장비 관리다. 모바일 사용은 지원 범위에서 제외하고 PC 1280px 이상 및 전시기를 기준으로 한다. 기존 모바일 검증 기록은 과거 이력이며 현재 수용 조건이 아니다.

## 목업 검토 후 확정 사항 (2026-10-03)

이 절은 앞선 모바일 지원·독립 시연 자료·미연동·결정 대기 설명보다 우선한다. 적용 대상은 docs/design/mockup.html 통합 목업이며 서버 구현 완료를 뜻하지 않는다.

- 일반 사용자는 병력 메뉴·조회·병력 엑셀 시트를 사용할 수 없고 근무자(야간)는 조회·내보내기 가능하다. 정비사는 부대 전체 병력을 조회하며 수정은 BNOC·관리자 권한이다.
- 장비 운영 명칭은 장비 관리로 변경했다. PC 최소 1280px와 전시기만 지원하며 모바일 화면 및 모바일 수용 조건은 제외한다.
- BNOC·관리자의 대리 접수를 추가했다. 실제 요청 부서와 접수 계정을 구분한다. 16시 보고 보관 기능과 준비 중 버튼은 제외하고 날짜별·기간별 엑셀만 유지한다.
- 정비사는 미확인 배정·공조·오늘 작업·보류 작업을, 일반 사용자는 내 요청·근무자·담당 부서를 먼저 본다. 엑셀 도구와 CPCON 전체 설명은 펼쳐서 사용한다.
- 새 운영 정비 일정은 담당 부서의 계획정비 작업을 생성하거나 기존 작업 하나에 연결한다. 작업 완료는 일정에 반영되며 양쪽 상세에서 이동할 수 있다. 기존 요청에 연결한 영향 일정의 취소는 원래 정비 요청을 취소하지 않는다. 자동 생성된 계획정비 작업만 일정 취소에 따라 집계에서 제외한다.
- 운영 구성의 장비는 장비 관리의 등록 자료를 연결한다. 기존 가상 구성 장비는 최초 실행 시 장비 목록으로 이관한다. 구성에서 삭제해도 장비 관리 원장은 유지하며 정비 기록이 있는 구성은 운영 종료로 보존한다.
- 제17비행단의 상위 조회 화면과 엑셀은 동일 브라우저에 저장한 BNOC 자료를 참조한다. 가상 비행단 A·B는 독립 예시 자료다. 여러 사용자·PC 사이의 동기화는 서버 구현 범위다.
- 신규 요청은 BNOC, 배정·재배정은 담당 부서, 공조 요청은 수신 부서, 작업 완료는 BNOC 알림으로 연결한다. 알림 읽음은 작업 확인과 별개다. 개인 정비사 지정은 현재 부서 단위 배정 범위를 확장하지 않는다.
- 지시사항은 제목·본문 직접 입력 및 게시 전 검토 방식이다. 자동 문서 분석이나 자동 요약으로 표시하지 않는다. 실제 날짜와 가상 업무 기준일을 구분하고 미등록 과거 근무 편성을 임의로 만들지 않는다.

검증: 관련 모델 테스트 36건, workflow.browser.cjs(권한·대리 접수·일정 연결·취소 분리·상위 조회·장비 참조), experience.browser.cjs(알림·읽음·테마·PC/전시기), export.browser.cjs(실제 XLSX 다운로드·기간·시트·권한), system-operations.browser.cjs(구성·이동·삭제·일정·저장 유지)를 통과했다.
