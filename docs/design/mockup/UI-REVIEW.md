# 화면 개선 및 후속 평가 · 2026-10-03

대상: `docs/design/mockup.html` 브라우저 목업. 실제 서버 인증·공유 저장 구현 완료를 의미하지 않는다.

## 부서별 정비 요약 비교표 (2026-10-05)

정비사 계정의 정비 현황에서 같은 대대 전체 부서의 관리대상·완료·미완료·진척도를 비교표로 보여준다. 기간 조회를 적용하면 비교표도 갱신되며 내 부서를 표시한다. 0건 진척도는 ‘—’다. 비교 모델은 집계 수치만 반환하고 타 부서 행의 상세 링크는 제공하지 않는다. 자기 부서 작업·추이·엑셀 범위와 BNOC·상위 조회자의 기존 동작은 유지한다.

검증: 정비·상위 조회 모델 16건, department-comparison.browser.cjs 통과. 통합·responsive-motion 두 진입점에서 정비사 4역할, 기간 변경·0건, 상세 접근 차단·자기 부서 엑셀, 1280px 라이트/다크 표시를 확인했다. 서버 권한 검증은 후속 범위다.

## 반영 내용

- 운영 구성의 전송체계를 정보체계로 변경하고, 기반통신체계 아래에 네트워크체계를 배치했다. 기존 저장 자료는 한 번만 변환하며 장비 식별자와 정비 일정 연결을 유지한다. 상위 조회 및 요약 명칭도 맞췄다.

- 장비 관리 → 정보보호 프로그램 → 공문 관리에서 업체 공문 원본을 삭제할 수 있다. 연결 장비 목록을 확인하고 파일명을 입력하면 원본과 모든 장비 연결을 삭제한다. 장비 및 설치현황은 유지한다. 연결 장비가 없는 공문도 관리하며, 특정 장비만 제외할 때는 기존 현황 수정의 연결 해제를 사용한다. 저장 실패 시 원본을 복원한다. `tests/equipment-documents.browser.cjs`에서 공유/미연결 공문 삭제, 취소, 파일명 검증, 저장 실패 복구와 재조회 유지를 검증했다.

- 2026-10-04 승인된 라이트모드 대비 시안을 적용했다. 페이지 배경, 카드 테두리·그림자, 입력창 경계, 표 헤더·행 구분선, 보조 문구 대비를 강화했다. 다크모드에는 적용하지 않는다.

- 다크모드 공통 버튼 배경이 추이 막대 색을 덮는 문제를 수정했다. 신규·완료·미완료와 범례를 같은 색으로 표시하며 마우스 오버 때도 유지한다.
- 현재 소속·이름·계급은 우측 상단에서 확인하고 클릭하면 부서·권한과 개인 설정을 연다. 본문 상단의 반복 정보와 사이드바 내부 스크롤은 제거했다. 알림·테마는 아이콘과 툴팁으로 표시하며 읽지 않은 알림 수를 유지한다. (2026-10-04 변경)
- 정비 목록·상세와 작업 연결 선택에서 내부 `W-PLAN-*`, `R-PLAN-*` 대신 ‘운영현황 계획정비’를 표시한다. 내부 식별자와 기존 연결은 유지한다.
- 장비 등록에서 사업명·사업년도를 한 번 입력하고 장비명·부서·망 종류를 행별로 추가한다. 전체 행 검증 후 한 번에 저장하며 실패하면 메모리 변경을 되돌리고 입력을 유지한다.
- 장비 삭제는 이름 확인 후 처리한다. 운영 구성 및 운영 종료 이력에 연결된 장비는 삭제하지 않는다. 삭제 장비의 공문 연결만 해제하고 다른 장비가 공유하는 공문은 유지한다.

## 운영현황 정비 집계 기준

새 정비 일정은 담당 부서의 계획정비 작업 1건을 생성하여 정비 현황에 포함한다. 기존 작업을 연결하면 새 작업을 생성하지 않는다. 신규는 등록·배정일, 완료는 실제 조치 완료일 기준이며 선택한 통계 기간과 부서 필터에 따른다. 예정일에만 집계되는 방식이 아니다.

자동 생성한 계획정비를 취소하면 집계에서 제외한다. 기존 접수 작업에 연결한 일정만 취소한 경우 원래 정비 작업은 유지한다. 일정 등록 화면에도 집계 안내를 추가했다.

## 후속 보완 평가

1. 우선순위 높음: 정비 현황에 ‘요청 정비 / 계획정비’ 구분 필터를 추가하면 업무 성격을 나누어 실적을 해석하기 쉽다. 현재는 합산하며 작업 목록에서 출처를 확인한다.
2. 우선순위 높음: 실운영 시 장비 관리번호·제조번호와 폐기/보존 규칙을 확정해야 한다. 같은 모델 여러 대는 정상 등록이므로 장비명 중복만으로 등록을 차단하지 않는다. 현재 삭제는 연결 없는 오등록 정리 용도다.
3. 후속 편의: 대량 도입 규모가 커지면 엑셀 붙여넣기·업로드와 저장 전 미리보기를 추가한다. 현재는 행 추가 방식이다.
4. 서버 구현 단계: 사용자별 권한 검사, 다중 사용자 저장 충돌, 변경 이력과 감사 기록을 서버에서 보장해야 한다. 현재 목업은 브라우저 저장이다.

검증: `tests/ui-improvements.browser.cjs`, `tests/workflow.browser.cjs`, `tests/account-settings.browser.cjs`, `tests/equipment.test.cjs`. 다크모드 그래프 및 일괄 등록 화면을 캡처하여 배치도 확인한다.
