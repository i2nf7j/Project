## 1. 범위와 결정 수준

본 문서는 UX 설계 산출물이다. 제품 코드, 실행 화면, 픽셀 단위 시각 검증 결과가 아니다. 저장소에서 재사용할 실행 화면·스타일은 이번 확인으로 확보하지 못했다. 아래 ASCII 도식은 정보 배치와 동작을 설명하며 최종 색상·간격을 확정하지 않는다.

**확정 요구사항:** 대시보드·정보통신 운영·부대운영·정비관리 상위 메뉴, BNOC 최초 접수·부서 배정, 정비 진행 내 일정 통합, CPCON·GPS 하위 트리, 부서 카드 안 계급순 병력 세로 목록, 정비반 직접 공조 수락, 정비반 조치 완료 후 BNOC 종결, 포함 정상 행만 부분 업로드, 기간 중복 제거, 16시 보고 원본 보관, 역할별 시연 계정, 부대별 권한, 브라우저 자동 갱신이다. 추가 조치·완료 작업 재개·재발 전용 연결은 제외한다.

**설계 제안:** 화면 배치, 동일 계급 내 이름순, 일반 사용자의 부대운영 기본 숨김, 미처리 공조가 있는 접수의 종결 제한, 공조 거절·철회 주체, 알림 상세 대상은 제안이다. Planner가 업무 규칙과 API 명세에 반영할 때 결정 수준을 유지한다. 미정 사항은 §10에 모았다.

## 2. 정보 구조와 화면 목록

### 최신 홈 배치 개정

아래 공통 탐색의 상위 네 메뉴는 왼쪽 패널에 배치한다. 왼쪽 위에는 로고·체계명을 둔다. 종전 상단 가로 메뉴 도식은 메뉴 계층 참고용이며 최종 위치는 왼쪽이다. 가운데 본문과 오른쪽 패널은 역할별로 구성한다.

```text
┌──────────┬─────────────────────────────┬─────────────────┐
│ 로고     │ 대시보드 / 부대·계정·갱신   │                 │
│ 메뉴     ├─────────────────────────────┤ 역할별 업무 알림│
│          │ 상단 작은 요약 카드         │ 미리보기·전체보기│
│          ├──────────────┬──────────────┤                 │
│          │ 본문 카드 1  │ 본문 카드 2  ├─────────────────┤
│          ├──────────────┼──────────────┤ 지시사항        │
│          │ 본문 카드 3  │ 본문 카드 4  │ 중요도·게시시각 │
└──────────┴──────────────┴──────────────┴─────────────────┘
```

본문 2×2와 상단 CPCON·GPS·날씨·날짜는 BNOC 첫 시안 제안이다. 역할별 홈에서는 카드의 종류와 크기도 바꿀 수 있다. 자유로운 위젯 편집 기능은 이번 제안에 포함하지 않는다.

| 역할 | 가운데 본문 기본안 | 오른쪽 패널 기본안 |
|---|---|---|
| BNOC | 특기별 운영현황, 정비 캘린더, 오늘 근무자, 부대 정비 요약 | 접수 대기·종결 대기, 대상 지시사항 |
| 정비부서 | 자기 부서 작업 요약·오늘 일정·근무·허용 운영현황 | 부서 배정 알림·공조 수신, 대상 지시사항 |
| 일반 사용자 | 정비 요청 버튼·내 요청 목록·내 일정·관련 근무 안내 | 본인 요청 처리 변경, 공개 대상 지시사항 |
| 상위 조회자 | 선택 부대 운영·정비·근무 요약, 읽기 전용 비교 | 주요 변동·대상 지시사항, 처리 버튼 없음 |

일반 사용자에게 부대 전체 정비 통계·접수 대기·권한 없는 상황단계를 표시하지 않는다. 개인 일정은 본인 요청 조치 예정일과 등록·조회 권한이 있는 본인 근무만 사용한다. 등록 자료가 없으면 빈 상태를 표시한다. 일반 사용자도 개인 대시보드를 첫 화면으로 제공하는 안으로 기존 시작 화면 제안을 조정한다.

BNOC 접수 대기 항목을 누르면 요청 ID를 유지하여 정비 접수 상세로 이동한다. 알림을 읽었다고 요청이 접수되지는 않는다. 오른쪽 지시사항은 팝업 기본 동작 대신 지속적으로 조회할 수 있게 하며 전시기에서는 별도 읽기 중심 배치를 사용한다. 좁은 화면에서는 패널을 접거나 본문 아래로 이동하고 중요한 업무 대기 표시를 유지한다.

네 상위 메뉴와 그 하위 항목은 왼쪽 패널에 표시하고 상단에는 공통 조작을 둔다. 대시보드는 첫 번째 독립 화면이다. 정보통신 상황은 묶음 제목이며 CPCON과 GPS 각각의 화면으로 이동한다. 등록·수정·업로드·공조는 화면 안 버튼이나 상세 패널로 제공하고 새 메뉴를 만들지 않는다.

```text
[대시보드] [정보통신 운영] [부대운영] [정비관리]
                        [허용 부대 선택] [알림] [전시기] [설정] [계정]
정보통신 운영                     부대운영          정비관리
 ├ 정보통신 운영현황               ├ 병력 현황      ├ 정비 요청
 └ 정보통신 상황                   ├ 근무자(야간)   ├ 정비 접수
   ├ CPCON                        └ 지시사항       ├ 정비 진행
   └ GPS 전파교란 위기경보단계                      └ 정비 현황
정비 진행 화면 안: [목록 / 캘린더] 전환, 일간·주간·월간 일정
```

| 화면 ID / 요구사항 | 화면과 정보 우선순위 | 화면 내 조작 / 역할 |
|---|---|---|
| UX-01 / COM-01·02 | 시연 로그인: 역할·소속을 식별할 수 있는 계정 안내, 로그인 입력 | 미리 생성된 계정으로 로그인. 회원가입 없음 |
| UX-02 / COM-04 | 대시보드: 긴급·미배정 정비, 운영상태·상황단계, 병력·야간 근무, 중요 지시 | BNOC 부대 전체·정비반 자기 부서의 상세 이동·전시기. 상위 조회자는 허용 부대 선택 |
| UX-03 / OPS-04 | 정보통신 운영현황: 체계 분류별 상태 카드, 변경 시각, 참고사항 | BNOC 상태 수정; 조회자는 읽기 전용 |
| UX-04 / OPS-04 | CPCON: 현재 단계·적용 시각·참고사항 | BNOC 수정. 단계 목록은 가상 시연 기준 결정 전까지 임의 확정하지 않음 |
| UX-05 / OPS-04 | GPS 전파교란 위기경보단계: 현재 단계·적용 시각·참고사항 | CPCON과 동일한 조작 형태, 데이터는 독립 |
| UX-06 / OPS-01·02 | 병력 현황: 부서별 계급순 인원 행, 상태별 보조 요약 | 날짜·부서·상태·이름 필터, BNOC 인원 상태 수정·양식·업로드 |
| UX-07 / OPS-03 | 근무자(야간): 관리 대대별 직책·근무자·소속·시작/종료 일시 | BNOC 직접 등록·수정·업로드; 상위 조회자는 허용 대대 자동 취합 |

| UX-12 / MNT-07 | 정비 진행 내 캘린더 보기: 일간·주간·월간, 계획정비/장애조치, 예정일 | 일정 항목에서 같은 작업 상세로 이동; 일정 미정 작업 별도 목록 제안 |
| UX-13 / COM-03·05 | 공통 알림함·설정: 소속과 역할, 변경 주체·시각 | 알림에서 권한 있는 상세 이동. 설정은 권한 사용자만, 별도 상위 탭 없음 |

일반 사용자는 정비 요청의 본인 신청을 시작 화면으로 제안한다. BNOC·상위 조회자는 대시보드, 정비사는 자기 부서 중심 대시보드에서 미확인·진행 작업을 눌러 정비 진행으로 이동하도록 제안한다. 대시보드는 메뉴 순서상 첫 번째다. 정비 접수는 BNOC에게만 표시하고 일반 사용자에게 타인 요청·부대 집계를 노출하지 않는다. 정비사의 병력·정보통신 운영 조회 범위는 구현 전 권한표로 명시한다.

대시보드 카드와 정비 현황의 상세 목록은 같은 기간·부대·부서·상태 필터를 사용한다. BNOC는 미배정 요청·종결 대기와 부서 비교를 우선하고, 정비반은 배정 미확인·작업 중·오늘 예정·지연과 자기 부서 완료 건수를 우선한다. 지연·미확인은 상태와 겹칠 수 있는 보조 지표이므로 상태 합계에 더하지 않는다.

## 3. 역할별 핵심 흐름

### 3.1. 일반 사용자 → BNOC 접수

후속 입력 자동화 보완: 계급·성명·사무실 전화번호는 시연 계정 프로필에서 자동 채운다. 실제 인트라넷 연동으로 표시하지 않는다. 아래는 제목·태그의 설계 제안이며 추천 태그를 자동 확정하지 않는다.

```text
정비 요청
계급·성명       중사 가상A               [자동 입력]
사무실 전화     DEMO-1001                [자동 입력]
요청 부서       보급대대 유류통제반       [소속 기본값]
내용            모니터 2대 정비 요청
                상세 설명을 이어서 입력할 수 있습니다.
태그            [미선택 v]               [추천: 모니터 / 선택]
희망 정비부서   [미지정 v]
추가 메모       [수량·범위 등 선택 입력]

제목 미리보기   [보급대대 유류통제반] 모니터 2대 정비 요청
                                         [요청 등록]
```

제목은 부서와 본문 첫 줄로 생성한다. 태그 미선택도 제출 가능하며 BNOC는 정비 접수에서 미분류 요청을 찾아 태그를 지정한다. 긴 본문에서 첫 줄을 잘라 표시하더라도 원문은 유지한다. 부서별 업무 안내에 네트워크체계팀의 랜선·모니터·PC 포맷 예시를 제공한다.

```text
로그인 → 정비 요청 → 부서별 업무 안내 확인 → 신규 신청
       → 장비·증상·희망 부서 입력(기본: 미지정) → 신청 완료
       → 본인 신청 상세에서 배정·조치·종결 확인

모든 신청(희망 부서 미지정/선택) → BNOC 정비 접수 → 부서 배정 및 승인
             → 부서 작업 생성·알림 → 정비반 정비 진행 → 작업 확인 → 진행·완료
```

희망 부서 옆에 ‘희망 부서는 선택사항이며 최종 담당 부서는 BNOC가 지정합니다’를 표시한다. 요청 부대·신고자는 로그인 정보에서 표시하여 임의 다른 부대 요청을 만들지 않도록 제안한다. 승인 제출 중 버튼은 잠그고, 다른 BNOC 담당자가 먼저 승인했으면 ‘이미 처리된 신청입니다’와 현재 담당·상태를 표시한다. 서버가 처리 결과를 확정한 뒤에만 성공으로 안내한다.

### 3.2. 정비반 공조 → 완료 → BNOC 종결

```text
A반 작업 상세 → 같은 대대 B반에 공조 요청 → B반 공조 수신 목록
             → B반 직접 수락 → B반 작업 1건 생성 → BNOC 알림
             → A·B반이 각각 자기 작업 조치 완료
             → 관련 작업 모두 완료 → BNOC 종결 대기 → BNOC 종결
```

수락 전 공조 요청은 작업 건수에서 제외한다. 공조 수락 버튼은 수신 부서에만 제공하고, 타 부서 작업은 필요한 범위의 조회만 제공한다. 수락 전후 접수 1건은 유지되며 작업 1건이 2건으로 증가한다. 재작업·반송·종결 취소 버튼은 만들지 않는다.

미처리 공조가 남으면 종결을 막고 ‘공조 요청 처리 필요’를 표시하는 것은 설계 제안이다. 거절은 수신 부서, 철회는 요청 부서가 사유와 함께 처리하도록 제안하며 BNOC 강제 철회 권한은 추가하지 않는다. 미완료 작업이나 남은 공조의 유무는 서버 판단값으로 받는다.

### 3.3. 병력·야간 근무

BNOC는 병력 화면에서 날짜를 선택하고 인원 행을 직접 수정하거나 파일을 검증한 뒤 정상 행을 적용한다. 인원 기준 명단과 날짜별 상태를 구분하고, 오늘 값이 없으면 ‘미입력’으로 남긴다. 야간 근무는 대대별 직접 등록 또는 업로드 후 허용된 상위 조회 화면에 자동 반영된다. 주간 상태 변경이 야간 명단을 자동 수정하지 않는다.

### 3.4. 계획·선조치와 통계

BNOC는 정비 진행에서 계획정비를 등록하고, 정비반은 선조치 등록 버튼에서 수행 내용과 시각을 입력한다. 선조치 건은 BNOC의 사후 확인 대상으로 식별한다. 구체적인 접수 생성·배정 전 처리 규칙은 아직 미정이다. 정비 현황에서 상세 작업과 상세 미등록 건수를 분리하여 확인하고, 16시 보고는 현재 현황과 별도로 읽는다.

부서 카드는 PC에서 2~3열, 좁은 화면은 1열로 제안한다. 인원은 서버가 제공한 계급 순서, 같은 계급 내 이름순, 동명이인은 식별번호순으로 안정 정렬하는 방식을 제안한다. 동명이인에는 식별번호를 보조 표시한다. 긴 부서명·성명은 줄바꿈하며 이름이 잘려 식별 불가능해지지 않게 한다.

인원 행을 누르면 BNOC는 ‘가상 계급·성명 / 기준일 / 현재 상태 / 새 상태 / 비고 / 저장’을 확인한다. 조회자는 상세만 본다. 상태 필터 적용 시 카드 요약은 필터 결과임을 표시한다. 인원이 많은 카드는 일부 표시와 ‘전체 N명 보기’를 명시하며 조용히 누락하지 않는다. 전시기는 전체 명단을 페이지로 순환한다.

### 4.2. UX-06 업로드 검증과 부분 적용

```text
병력 업로드 / 가상 A대대 / 선택 기준일
1 파일 선택 → 2 검증·미리보기 → 3 적용 결과

파일: demo-personnel.xlsx      정상 28행 · 오류 2행
파일에서 빠진 인원의 당일 상태는 유지됩니다.
행 | 인원 ID  | 이름   | 기존 → 적용 예정   | 검증
 2 | DEMO-001 | 가상A  | 주간 → 근무 오프  | 변경
 3 | DEMO-002 | 가상B  | 휴가 → 주간       | 변경
30 | UNKNOWN  | 가상X  | 적용 안 함        | 식별번호 오류
31 | DEMO-030 | 가상Y  | 기존 값 유지      | 상태값 오류
                              [취소] [정상 28행 적용]

[오류 행과 수정 방법 보기] [수정 파일 재업로드] [명단 확인]
```

‘업로드 완료’ 하나로 부분 실패를 숨기지 않는다. 미리보기는 신규 일일 상태·변경·동일·파일 누락·오류를 구분하고 전후 값을 보여준다. 기준 명단에 없는 인원을 일일 상태 업로드로 자동 생성하는 것은 확정하지 않는다. 빈 상태는 삭제가 아니라 오류다. 파일 내부 동일 인원·기준일 중복은 해당 행 모두 오류로 처리한다.

적용 직전 타 사용자가 바꾼 행은 충돌로 남기고 최신 값과 다시 비교한다. 서버가 확인한 실제 결과만 성공 수로 표시한다. 전체 파일 재업로드 시 이미 같은 28행은 ‘변경 없음’으로 처리하고 수정된 2행만 갱신한다. 읽을 수 없는 파일·필수 열 누락·권한 없는 부대 대상은 파일 전체 오류로 구분한다.

### 4.4. UX-09 정비 현황과 16시 기록

```text
정비 현황 [월간 / 날짜 범위] [기간 선택] [부서 전체]
[현재 현황] [16시 일일 보고: 날짜 선택]
보고 기준: 현재 16:30 / 완료는 정비반 조치 완료 기준
접수 7건 · 종결 3건                 작업 대상 10건 · 완료 8건

부서 | 출처          | 대상 | 대기 | 진행 | 보류 | 완료 | 미완료 | 진척도
A반  | 상세 자동집계 |  6   |  0   |  1   |  0   |  5   |  1     | 83.3%
A반  | 건수 입력분   |  4   |  —   |  —   |  —   |  3   |  1     | 75.0%
합계 |               | 10   |  —   |  —   |  —   |  8   |  2     | 80.0%
                                 [상세 미등록 업무 건수 입력]
16시 보고 조회 시: 당시 완료 6/10건, 현재값으로 갱신하지 않음
```

주간·월간 대상은 작업 ID 중복 제거 결과를 표시하며 일일 합계를 재계산하지 않는다. 16시 보고는 일일 기록임을 명시한다. 미생성 날짜는 ‘16시 보고 기록 없음’으로 표시하고 현재값을 대신 넣지 않는다. 수동 입력에는 ‘상세 작업으로 등록하지 않은 업무만 입력’ 안내, 이월 출처·신규·완료·잔량을 제시한다. 실제 업무 중복을 자동으로 완전히 찾아준다고 안내하지 않는다. 취소·정정 조작은 권한 확정 후 상세화한다.

접수는 요청 ID 기준, 부서별 접수 건은 ‘부서 배정건’으로 표시하며 작업 ID 기준으로 센다. 한 요청을 세 부서가 수행하면 접수 1건·부서 배정 3건이다. 기간 신규 배정건과 이전 기간 이월을 분리하고 관리대상은 이월과 신규의 중복 없는 합계다. 상세 작업의 관리대상은 대기+진행(작업 중)+보류+완료, 미완료는 대기+진행+보류다. 완료는 조치 완료이며 BNOC 종결과 다르다. 수량만 입력한 업무는 진행·보류를 추정하지 않고 ‘상세 상태 미집계’로 표시한다.

대시보드에는 동일 기준의 건수 카드와 부서별 상태 막대그래프를 제안한다. 그래프보다 숫자를 먼저 읽게 하고, 카드를 누르면 해당 필터의 정비 현황 또는 정비 진행으로 이동한다. 정비반에는 자기 부서만, BNOC에는 부대 전체와 부서 비교를 제공한다. 기간 도중 접수된 작업이나 이월이 있는 경우에도 선택 기간·기준시각을 항상 표시한다. 그래프 상태 비율은 상세 작업만 기준으로 하고 건수 입력분은 별도 요약하여 분모를 숨기지 않는다.

### 4.5. UX-02 전시기

```text
가상 A대대 종합상황            09:15 갱신 · 연결됨 · 페이지 1/3
중요 지시: 가상 정기 점검 안내                         [고정 영역]
+---------------------------+ +-------------------------------+
| 긴급 2 · 미배정 1          | | 정보통신 운영 / 상황단계      |
| 긴급 장애와 담당·상태     | | 체계별 상태 / CPCON / GPS     |
+---------------------------+ +-------------------------------+
+---------------------------+ +-------------------------------+
| 부서별 작업 대상·완료     | | 야간 근무 직책·가상 근무자    |
```

전시기는 편집 도구와 좌측 메뉴를 숨기고 읽기 중심으로 제공한다. 중요 지시는 팝업으로 가리지 않는다. 긴 목록은 글씨를 줄이기보다 페이지로 나누고 현재 페이지와 순환 상태를 표시한다. 순환 간격은 사용자에게 보이는 제어값으로 두는 제안이며 고정 시간을 확정하지 않는다. 부대는 선택한 범위를 유지하고 자동으로 다른 부대로 전환하지 않는다. 연결 끊김 때 마지막 데이터와 갱신 시각을 유지하면서 ‘연결 끊김·최신 정보 아님’을 계속 표시한다.

## 5. 공통 상호작용과 상태별 UX

| 상태 | 표현과 동작 |
|---|---|
| 첫 조회·로딩 | 영역 형태를 유지하는 로딩 표시. 아직 수신하지 않은 수치를 0으로 표시하지 않음 |

| 다른 사용자 변경 | 입력 초안을 유지하고 ‘새 변경 있음’ 알림. 저장 충돌은 최신값 비교 후 재시도 |
| 연결 끊김 | 마지막 갱신 시각과 최신성 경고, 재연결 상태 표시. 연결 회복 시 권한 범위 재조회 |
| 권한 없음 | 내용 유출 없이 권한 없음 안내 및 허용 화면 이동. 버튼 숨김만으로 보안 처리하지 않음 |
| 세션 만료 | 로그인 안내. 재로그인 전 다른 계정에 기존 부대 자료를 계속 노출하지 않음 |
| 부대 전환 | 이전 부대 내용을 지우고 로딩 후 새 부대 표시. 편집 중이면 저장/이동 취소 선택 |

비편집 영역은 자동 갱신하되 편집 중인 입력과 키보드 포커스를 바꾸지 않는다. 새로운 긴급 작업은 알림과 목록 강조로 전달하고 작성 중 상세를 강제로 닫지 않는다. 알림 읽음과 작업 확인은 별개다. 단순 알림 열람을 작업 확인으로 기록하지 않도록 제안한다.

작업 알림의 수신 단위는 정비부서로 확정한다. 개인 담당자 지정 여부와 무관하게 부서 구성원에게 표시하며 개인별 읽음과 부서 작업 확인 주체·시각을 구분한다.

## 6. 시각·접근성 설계 기준 제안

- 업무 화면 본문은 16px, 제목은 24px 이상을 시작값으로 사용한다. 전시기 본문은 24px 이상을 시작값으로 하며 실제 해상도와 시청 거리에서 조정한다. 검증 전 가독성 충족을 단정하지 않는다.
- 기본 표면은 밝은 배경, 짙은 본문, 주 동작은 한 가지 강조색을 사용한다. 긴급·오류는 붉은 계열, 보류·주의는 황색 계열, 완료·정상은 녹색 계열을 사용하되 반드시 상태명을 병기한다.
- 작업상태, 일반/긴급, 지연 여부는 별도 배지로 표현한다. ‘빨간색 = 모든 문제’처럼 다른 의미를 합치지 않는다.
- 버튼과 입력은 라벨·키보드 포커스를 제공하고 아이콘 단독 버튼에는 이름을 제공한다. 팝업은 닫힌 뒤 호출 버튼으로 포커스를 돌린다.
- 좁은 화면은 부서 카드 1열, 필터 줄바꿈, 편집 패널 전체폭으로 전환한다. 캘린더는 동일 날짜의 목록 전환을 제공하는 방식을 제안한다.
- 상태 변경·부분 업로드 결과는 화면에 남겨 사용자가 다시 확인할 수 있게 한다. 잠깐 나타났다 사라지는 알림만 사용하지 않는다.

## 9. 구현 전달 순서 제안

1. 시연 로그인·네 상위 메뉴·정비 요청·BNOC 승인/배정·공조 요청과 직접 수락·정비사 조치 완료·BNOC 종결·두 화면 갱신을 첫 상세 설계 범위로 묶는다.
2. 향후 코드 구현에서는 기본 접수·종결을 먼저 연결하고 같은 첫 기능 묶음 안에서 공조·중복 처리·권한 오류 상태를 연결한다. 공조를 후속 범위로 제외하지 않는다.
3. 부서별 병력 카드·부분 업로드와 야간 근무 취합을 설계·구현한다.
4. 통계·16시 기록·계획정비·일정·운영상태·상황단계·지시·전시기 설계를 확장한다.

이는 상세화·구현 순서 제안이며 범위 축소나 현재 제품 코드 구현 지시가 아니다. 최종 구현 지시는 Planner가 UX와 기술 검토를 맞춘 후 작성한다.

## 10. Planner 조율이 필요한 사항

후속 사용자 답변으로 다음 사항은 확정되었다. 아래 기존 미정 목록보다 우선한다.

- 병력은 부서별 블록 안 계급순 세로 목록으로 표시하며 주간·오프·휴가·출장을 사용한다. 미입력 상태는 유지한다.
- 정비부서의 자기 부서 대시보드를 기본으로 하고 같은 대대 타 부서 정비 요약 조회를 허용한다. 타 부서 수정·병력·운영정보 조회 권한을 의미하지 않는다.
- 잘못 배정된 작업 상세에 ‘재배정 요청’과 사유 입력을 제공하고 BNOC가 정비 접수에서 담당 변경을 확정한다. 기존 작업을 복제하지 않는다. 공조는 별도 동작이다.
- 요청서 1개는 1건이다. ‘모니터 10대’ 등은 추가 메모에 적고 단일 부서 작업은 1건으로 처리한다. 업무 안내 예시는 네트워크체계팀의 랜선 고장·모니터 정비·PC 포맷이다.
- 확인은 시작과 분리한다. 작업 예정·작업 중·보류·완료를 사용하고 애매하거나 대기할 때 사유를 적어 보류한다.
- 전월 접수·당월 완료는 당월 완료 실적이다. 현재 잔량과 선택 기간 이월·신규 배정·완료·잔량의 기준을 표시한다.
- 전시기는 약 75인치 TV, 브라우저는 Edge를 우선한다. 픽셀 해상도·배율·시청 거리는 미정이다. FHD·4K는 후속 시안 비교 후보이지 확인된 출력 환경이 아니다.

근무자(야간) 화면 보완 예시:

```text
가상 A대대 / 근무 기준일
구역·직책        계급       성명         전화번호
통신일직         대위       가상A        DEMO-1001
작통일직         중위       가상B        DEMO-1002
생활관 근무자    중사       가상C        DEMO-1003
```

구역·직책별로 묶고 대대별 등록·자동 취합을 유지한다. 전화번호는 가상 내선 표시 예시이며 실제 개인정보를 사용하지 않는다. 시작·종료 일시와 근무자 소속은 상세에서 확인한다.

| 우선순위 | 쟁점 | 권장안 / 진행 가능한 범위 |
|---|---|---|
| 첫 구현 전 | 일반 사용자·정비사의 부대운영 조회, 설정 담당 | 일반 사용자는 본인 신청 중심, 설정은 지정 권한만. 승인 없는 부대 데이터 노출 금지 |
| 공조 구현 전 | 미처리 공조 종결, 거절·철회 | 공조 미처리 시 종결 제한, 수신 거절·요청자 철회 제안. BNOC 사전 승인 복원하지 않음 |
| 업로드 구현 전 | 신규 기준 명단 등록·야간 근무 재업로드 키 | 명단 업로드와 일일 상태 구분, 안정 식별키 사용. UX 부분 반영 원칙 유지 |
| 관련 기능 전 | 취소·오입력 정정·수동 건수 정정 | 권한·이력 확정 후 버튼 배치. 재작업 절차와 구분 |
| 시연 자료 작성 전 | 계급 순서·전체 상태·운영체계·CPCON/GPS 단계 | 가상 자료 목록 승인 후 적용. 실제 단계 체계 임의 추정 없음 |
| 알림 상세화 전 | 상세 수신 범위·지시 재표시 | 요청/수락은 관련 정비반과 BNOC, 신청자에게 본인 처리변경 제안. 지시 개정 재표시는 별도 결정 |
