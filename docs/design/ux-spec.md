## 2. 정보 구조와 화면 목록

### 최신 홈 배치 개정

아래 공통 탐색의 상위 네 메뉴는 왼쪽 패널에 배치한다. 왼쪽 위에는 로고·체계명을 둔다. 종전 상단 가로 메뉴 도식은 메뉴 계층 참고용이며 최종 위치는 왼쪽이다. 가운데 본문과 오른쪽 패널은 역할별로 구성한다.

```text
┌──────────┬─────────────────────────────┬─────────────────┐
│ 로고     │ 대시보드 / 부대·계정·갱신   │                 │
│ 메뉴     ├─────────────────────────────┤ 역할별 업무 알림│
│          │ 상단 작은 요약 카드         │ 미리보기·전체보기│
│          ├──────────────┬──────────────┤                 │
│          │ 본문 카드 1  │ 본문 카드 2  ├─────────────────┤
│          ├──────────────┼──────────────┤ 지시사항        │
│          │ 본문 카드 3  │ 본문 카드 4  │ 중요도·게시시각 │
└──────────┴──────────────┴──────────────┴─────────────────┘
```

본문 2×2와 상단 CPCON·GPS·날씨·날짜는 BNOC 첫 시안 제안이다. 역할별 홈에서는 카드의 종류와 크기도 바꿀 수 있다. 자유로운 위젯 편집 기능은 이번 제안에 포함하지 않는다.

| 역할 | 가운데 본문 기본안 | 오른쪽 패널 기본안 |
|---|---|---|
| BNOC | 특기별 운영현황, 정비 캘린더, 오늘 근무자, 부대 정비 요약 | 접수 대기·종결 대기, 대상 지시사항 |
| 정비부서 | 자기 부서 작업 요약·오늘 일정·근무·허용 운영현황 | 부서 배정 알림·공조 수신, 대상 지시사항 |
| 일반 사용자 | 정비 요청 버튼·내 요청 목록·내 일정·관련 근무 안내 | 본인 요청 처리 변경, 공개 대상 지시사항 |
| 상위 조회자 | 선택 부대 운영·정비·근무 요약, 읽기 전용 비교 | 주요 변동·대상 지시사항, 처리 버튼 없음 |

일반 사용자에게 부대 전체 정비 통계·접수 대기·권한 없는 상황단계를 표시하지 않는다. 개인 일정은 본인 요청 조치 예정일과 등록·조회 권한이 있는 본인 근무만 사용한다. 등록 자료가 없으면 빈 상태를 표시한다. 일반 사용자도 개인 대시보드를 첫 화면으로 제공하는 안으로 기존 시작 화면 제안을 조정한다.

BNOC 접수 대기 항목을 누르면 요청 ID를 유지하여 정비 접수 상세로 이동한다. 알림을 읽었다고 요청이 접수되지는 않는다. 오른쪽 지시사항은 팝업 기본 동작 대신 지속적으로 조회할 수 있게 하며 전시기에서는 별도 읽기 중심 배치를 사용한다. 좁은 화면에서는 패널을 접거나 본문 아래로 이동하고 중요한 업무 대기 표시를 유지한다.

네 상위 메뉴와 그 하위 항목은 왼쪽 패널에 표시하고 상단에는 공통 조작을 둔다. 대시보드는 첫 번째 독립 화면이다. 정보통신 상황은 묶음 제목이며 CPCON과 GPS 각각의 화면으로 이동한다. 등록·수정·업로드·공조는 화면 안 버튼이나 상세 패널로 제공하고 새 메뉴를 만들지 않는다.

```text
[대시보드] [정보통신 운영] [부대운영] [정비관리]
                        [허용 부대 선택] [알림] [전시기] [설정] [계정]
정보통신 운영                     부대운영          정비관리
 ├ 정보통신 운영현황               ├ 병력 현황      ├ 정비 요청
 └ 정보통신 상황                   ├ 근무자(야간)   ├ 정비 접수
   ├ CPCON                        └ 지시사항       ├ 정비 진행
   └ GPS 전파교란 위기경보단계                      └ 정비 현황
정비관리 추가 하위 탭: 정비 안내·연락처
정비 진행 화면 안: [목록 / 캘린더] 전환, 일간·주간·월간 일정
```

일반 사용자는 정비 요청의 본인 신청을 시작 화면으로 제안한다. BNOC·상위 조회자는 대시보드, 정비사는 자기 부서 중심 대시보드에서 미확인·진행 작업을 눌러 정비 진행으로 이동하도록 제안한다. 대시보드는 메뉴 순서상 첫 번째다. 정비 접수는 BNOC에게만 표시하고 일반 사용자에게 타인 요청·부대 집계를 노출하지 않는다. 정비사의 병력·정보통신 운영 조회 범위는 구현 전 권한표로 명시한다.

대시보드 카드와 정비 현황의 상세 목록은 같은 기간·부대·부서·상태 필터를 사용한다. BNOC는 미배정 요청·종결 대기와 부서 비교를 우선하고, 정비반은 배정 미확인·작업 중·오늘 예정·지연과 자기 부서 완료 건수를 우선한다. 지연·미확인은 상태와 겹칠 수 있는 보조 지표이므로 상태 합계에 더하지 않는다.

### CPCON 대시보드·상세 탭 (2026-09-16)

콘텐츠와 단계 정의는 [기획서 §6.2](../../PROPOSAL.md#62-정보통신-운영현황-및-상황)를 따른다. DB 연결 없이 먼저 완성할 화면 범위다.

- 대시보드 카드: `CPCON V · 정상` 형식으로 현재 단계만 간결하게 전달한다. 단계별 배지·배경 색상을 적용하고 카드 선택 시 정보통신 운영 → 정보통신 상황 → CPCON 상세 탭으로 이동한다.
- 색상 순서: V 정상은 연한 녹색, IV 알파는 녹색, III 브라보는 노란색, II 찰리는 주황색, I 델타는 빨간색이다. 숫자가 작아질수록 위협이 높아진다는 안내를 상세 탭에 표시한다.
- 상세 탭 순서: CPCON 정의·목적·INFOCON 명칭 변경 설명 → 현재 단계·적용 시각·참고사항 → V~I 전체 단계의 한글·영문 명칭과 설명. 현재 단계에 `현재 단계` 문구와 강조 테두리를 함께 표시한다.
- 설정 권한: 관리자 또는 사이버(정보보호) 특기 직렬 사용자에게만 허용된 부대의 단계 설정 조작을 제공한다. BNOC 역할만으로는 설정 조작을 표시하지 않는다. 그 외 사용자는 조회 권한 범위에서 읽기 전용으로 표시한다. DB 없는 시연에서는 화면의 권한별 표시를 확인하고, 실제 변경 권한 강제는 후속 서버 연동에서 검증한다.
- 가독성: 색상만으로 단계를 구분하지 않고 로마 숫자와 한글 명칭을 항상 병기한다. 연한 녹색·노란색 배경에는 짙은 글자를 사용한다.
- 시연 상태: 현재 값은 시연 데이터임을 표시하고 적용 시각이 없는 경우 `미지정`으로 표시한다. 대시보드와 상세 탭은 같은 시연 값을 참조한다. 실제 발령값으로 오인할 임의의 현재 시각을 생성하지 않는다.
- 확인 기준: 다섯 단계의 시연 값을 각각 적용했을 때 두 화면의 로마 숫자·명칭·색상이 일치하고, 카드에서 상세 탭으로 이동하며, 개요와 모든 단계 설명을 DB 없이 읽을 수 있다.

## 3. 역할별 핵심 흐름

### 3.1. 일반 사용자 → BNOC 접수

후속 입력 자동화 보완: 계급·성명·사무실 전화번호는 시연 계정 프로필에서 자동 채운다. 실제 인트라넷 연동으로 표시하지 않는다. 제목은 요청 대상·선택 수량·요청 유형을 조합하는 확정 기준을 따른다. 태그 추천은 설계 제안이며 추천 태그를 자동 확정하지 않는다. 태그 선택은 확정된 부서별 단일 태그 기준을 따른다.

2026-10-06 첫 시연 계정 확정: 개인 설정에는 관리자가 계정·소속·권한을 사전 등록한다는 안내와 변경 시 관리자 문의 안내를 표시한다. 이름·계급·소속·권한의 사용자 직접 수정은 제공하지 않는다. 계정·권한 신청, 승인 대기, 승인·반려 화면은 첫 시연에서 제외한다. 실제 로그인·로그아웃·권한 오류 처리는 포함하며 현재 목업의 역할 선택 시연과 구분한다.

```text
정비 요청
계급·성명       중사 가상A               [자동 입력]
사무실 전화     DEMO-1001                [자동 입력]
요청 부서       보급대대 유류통제반       [소속 기본값]
내용            모니터 2대 정비 요청
                상세 설명을 이어서 입력할 수 있습니다.
요청 유형       [증설 v] 점검 / 증설 / 설치 / 이전 / 불용 / 기타
요청 대상       [모니터]
수량 (선택)     [2] 단위 [대]
업무 태그       [미지정 v]               [추천: 모니터 / 선택]

                                         [요청 등록]
```

제목은 `[요청 부서] 요청 대상 [수량·단위] 요청 유형 요청`으로 생성한다. 유형은 점검·증설·설치·이전·불용·기타 중 하나이며 대상과 유형은 필수다. 수량은 선택 입력으로, 입력하면 단위와 함께 표시하고 비워두면 생략한다. 수량 단위는 기본 대로 제안하며 변경할 수 있다. 대상·유형·수량·단위 변경 시 제목 미리보기를 갱신한다. 태그 미선택도 제출 가능하며 미지정으로 표시한다. 희망 부서별 목록에서 최대 1개를 선택하고 BNOC가 확정 주관 부서에 맞게 대표 태그를 확인한다. 본문의 구어체·숫자를 분석해 제목에 넣지 않으며 본문은 그대로 보존한다. 부서별 업무 안내에 네트워크체계팀의 랜선·모니터·PC 포맷 예시를 제공한다.

```text
로그인 → 정비 요청 → 부서별 업무 안내 확인 → 신규 신청
       → 장비·증상·희망 부서 입력(기본: 미지정) → 신청 완료
       → 본인 신청 상세에서 배정·조치·종결 확인

모든 신청(희망 부서 미지정/선택) → BNOC 정비 접수 → 부서 배정 및 승인
             → 부서 작업 생성·알림 → 정비반 정비 진행 → 작업 확인 → 진행·완료
```

희망 부서 옆에 ‘희망 부서는 선택사항이며 최종 담당 부서는 BNOC가 지정합니다’를 표시한다. 요청 부대·신고자는 로그인 정보에서 표시하여 임의 다른 부대 요청을 만들지 않도록 제안한다. 승인 제출 중 버튼은 잠그고, 다른 BNOC 담당자가 먼저 승인했으면 ‘이미 처리된 신청입니다’와 현재 담당·상태를 표시한다. 서버가 처리 결과를 확정한 뒤에만 성공으로 안내한다.

### 3.2. 정비반 공조 → 완료 → BNOC 종결

```text
A반 작업 상세 → 같은 대대 B반에 공조 요청 → B반 공조 수신 목록
             → B반 직접 수락 → B반 작업 1건 생성 → BNOC 알림
             → A·B반이 각각 자기 작업 조치 완료
             → 관련 작업 모두 완료 → BNOC 종결 대기 → BNOC 종결
```

수락 전 공조 요청은 작업 건수에서 제외한다. 공조 수락 버튼은 수신 부서에만 제공하고, 타 부서 작업은 필요한 범위의 조회만 제공한다. 수락 전후 접수 1건은 유지되며 작업 1건이 2건으로 증가한다. 재작업·반송·종결 취소 버튼은 만들지 않는다.

2026-10-05 확정: 대기 공조에는 수신 부서의 수락·거절, 요청 부서의 철회 버튼을 표시한다. 거절·철회 다이얼로그는 사유를 필수 입력받고, 완료 후 요청·수신 부서와 BNOC·관리자가 처리 이력의 사유·처리자·시각을 조회한다. 처리된 공조는 다시 변경하지 않는다. BNOC 강제 거절·철회 버튼은 두지 않는다. 모든 작업 완료 후 대기 공조가 남으면 ‘공조 처리 대기’, 없으면 ‘종결 대기’로 표시하며 종결 버튼도 같은 조건을 사용한다. 실제 제품은 서버 판단값을 사용한다.

### 3.3. 병력·야간 근무

BNOC·관리자는 병력 화면에서 날짜를 선택하고 기간 상태를 직접 수정하거나 파일을 검증한 뒤 정상 행을 적용한다. 인원 기준 명단·기간 상태·근무 편성·날짜별 확인 기록을 구분한다. 표시 우선순위는 직접 지정 상태 > 자동 오프 > 기본 주간이다. 명단에 연결한 당직·야간은 시작일 다음 날 자동 오프이며 직접 지정한 당직·야간도 다음 날에 반영한다. 직접 지정 기간이 겹치면 마지막 적용이 우선하고 기간 종료 후 해당 날짜의 자동 오프 조건을 다시 계산한다. 명단 외 근무자는 자동 연결하지 않는다. 병력 상태 변경이 근무 편성을 역으로 수정하지 않는다.

확인 완료는 날짜별 확인자·확인 시각으로 별도 표시한다. 기간 상태 변경 시 해당 기간과 종료 다음 날, 근무 편성 변경 시 시작일 다음 날의 확인을 해제한다. 인원 기본정보 수정 시 기존 확인 기록을 해제한다. 기본 주간을 확인 완료로 표현하지 않는다. 상세 업무 기준은 product.md §4를 따른다.

### 3.4. 계획·선조치와 통계

BNOC는 정비 진행에서 계획정비를 등록하고, 정비반은 선조치 등록 버튼에서 수행 내용과 시각을 입력한다. 선조치 건은 BNOC의 사후 확인 대상으로 식별한다. 구체적인 접수 생성·배정 전 처리 규칙은 아직 미정이다. 정비 현황에서 상세 작업과 상세 미등록 건수를 분리하여 확인하고 적용 기간의 엑셀을 내보낸다. 16시 보고 조회·보관은 제공하지 않는다.

조치 완료 버튼은 결과 입력을 확인하고 제출 중 재클릭을 막는다. 완료는 작업 단위, 종결은 접수 단위임을 문구와 위치로 구분한다. BNOC 종결 대기 필터에서 접수별 관련 작업 결과를 확인하고 종결한다. BNOC 정비 접수 메뉴에 종결 대기를 두되 연결된 접수 상세를 공통 사용하여 접수·작업 내용을 중복 입력하지 않는다.

### 4.4. UX-09 정비 현황과 엑셀

정비사 화면에는 조회 조건 바로 아래에 ‘같은 대대 부서별 정비 요약’ 비교표를 표시한다(2026-10-05 사용자 선택). 열은 부서·관리대상·완료·미완료·진척도이며, 적용한 조회 기간을 모든 부서에 동일하게 사용한다. 내 부서를 표시하고 0건의 진척도는 ‘—’로 나타낸다. 표는 요약 전용으로 타 부서 상세 링크를 두지 않는다. 기존 자기 부서 요약·추이·상세 및 엑셀 내역과 범위를 설명으로 구분한다. BNOC·관리자의 기존 부서 필터·그래프와 상위 조회자 화면은 유지한다.

2026-09-16 조회 요구사항: 상단에 `부서: 전체 / 개별 부서`, `기간: 일간 / 주간 / 월간 / 직접 지정`, 시작일·종료일과 조회 버튼을 제공한다. 부서 선택지는 기존 조회 권한 범위만 제공한다. 요약 카드·그래프·목록은 같은 조회 조건을 사용하며 적용 중인 부서와 기간을 항상 표시한다.

사용자 선택에 따라 부서별 작업 건수를 기본 집계 축으로 사용한다. 그래프 구성은 다음과 같다:

- 요약 카드에는 선택 기간의 관리대상·신규·완료·미완료를 표시한다. 신규는 이월과 구분하고 완료·미완료가 관리대상의 구성 요소임을 드러낸다.
- 부서 비교는 가로 누적 막대의 완료·미완료와 총 관리대상 건수를 표시한다. 특정 부서 선택 시 그 부서의 값만 표시한다.
- 기간 추이는 신규·완료 건수를 날짜 순으로 표시한다. 표시 간격은 일·주·월 단위로 선택하고 각 구간은 조회 기간 안에서 집계한다. 신규와 완료는 서로 다른 사건이며 합계 작업 건수로 더하지 않는다.
- 그래프에 숫자와 범례를 병기하고 하단 표에서 같은 값을 확인할 수 있게 한다. 막대·추이 구간 선택 시 해당 부서·기간·지표의 상세 목록으로 연결한다. 상세 미등록 건수는 개별 작업 목록을 만들어내지 않고 건수 입력 내역으로 구분한다.
- 부서별 작업 수에 주관·공조 구분을 함께 제공한다. 상태별 완료·미완료와 참여 구분은 같은 작업의 다른 분류이므로 합산하지 않는다. 태그별 그래프는 후속 구현하며 접수·작업별 단일 태그와 미지정 집계 기준을 따른다.

```text
정비 현황 [월간 / 날짜 범위] [기간 선택] [부서 전체]
[현재 현황] [기간별 엑셀 다운로드]
보고 기준: 현재 16:30 / 완료는 정비반 조치 완료 기준
접수 7건 · 종결 3건                 작업 대상 10건 · 완료 8건

부서 | 출처          | 대상 | 대기 | 진행 | 보류 | 완료 | 미완료 | 진척도
A반  | 상세 자동집계 |  6   |  0   |  1   |  0   |  5   |  1     | 83.3%
A반  | 건수 입력분   |  4   |  —   |  —   |  —   |  3   |  1     | 75.0%
합계 |               | 10   |  —   |  —   |  —   |  8   |  2     | 80.0%
                                 [상세 미등록 업무 건수 입력]
엑셀 다운로드 시: 적용 기간·부서·집계 기준을 함께 표시
```

주간·월간 대상은 작업 ID 중복 제거 결과를 표시하며 일일 합계를 재계산하지 않는다. 16시 보고 및 준비 중 버튼은 제외하고 날짜별 통합·기간별 정비 엑셀을 제공한다. 현재 명단·운영 상태를 포함하는 파일에는 현재값이라는 기준을 표시한다. 수동 입력에는 ‘상세 작업으로 등록하지 않은 업무만 입력’ 안내, 이월 출처·신규·완료·잔량을 제시한다. 실제 업무 중복을 자동으로 완전히 찾아준다고 안내하지 않는다. 취소·정정 조작은 권한 확정 후 상세화한다.

접수는 요청 ID 기준, 부서별 접수 건은 ‘부서 배정건’으로 표시하며 작업 ID 기준으로 센다. 한 요청을 세 부서가 수행하면 접수 1건·부서 배정 3건이다. 기간 신규 배정건과 이전 기간 이월을 분리하고 관리대상은 이월과 신규의 중복 없는 합계다. 상세 작업의 관리대상은 대기+진행(작업 중)+보류+완료, 미완료는 대기+진행+보류다. 완료는 조치 완료이며 BNOC 종결과 다르다. 수량만 입력한 업무는 진행·보류를 추정하지 않고 ‘상세 상태 미집계’로 표시한다.

대시보드에는 동일 기준의 건수 카드와 부서별 상태 막대그래프를 제안한다. 그래프보다 숫자를 먼저 읽게 하고, 카드를 누르면 해당 필터의 정비 현황 또는 정비 진행으로 이동한다. 정비반에는 자기 부서만, BNOC에는 부대 전체와 부서 비교를 제공한다. 기간 도중 접수된 작업이나 이월이 있는 경우에도 선택 기간·기준시각을 항상 표시한다. 그래프 상태 비율은 상세 작업만 기준으로 하고 건수 입력분은 별도 요약하여 분모를 숨기지 않는다.

| 다른 사용자 변경 | 입력 초안을 유지하고 ‘새 변경 있음’ 알림. 저장 충돌은 최신값 비교 후 재시도 |

| 세션 만료 | 로그인 안내. 재로그인 전 다른 계정에 기존 부대 자료를 계속 노출하지 않음 |

비편집 영역은 자동 갱신하되 편집 중인 입력과 키보드 포커스를 바꾸지 않는다. 새로운 긴급 작업은 알림과 목록 강조로 전달하고 작성 중 상세를 강제로 닫지 않는다. 알림 읽음과 작업 확인은 별개다. 단순 알림 열람을 작업 확인으로 기록하지 않도록 제안한다.

작업 알림의 수신 단위는 정비부서로 확정한다. 개인 담당자 지정 여부와 무관하게 부서 구성원에게 표시하며 개인별 읽음과 부서 작업 확인 주체·시각을 구분한다.

## 6. 시각·접근성 설계 기준 제안

- 업무 화면 본문은 16px, 제목은 24px 이상을 시작값으로 사용한다. 전시기 본문은 24px 이상을 시작값으로 하며 실제 해상도와 시청 거리에서 조정한다. 검증 전 가독성 충족을 단정하지 않는다.
- 기본 표면은 밝은 배경, 짙은 본문, 주 동작은 한 가지 강조색을 사용한다. 긴급·오류는 붉은 계열, 보류·주의는 황색 계열, 완료·정상은 녹색 계열을 사용하되 반드시 상태명을 병기한다.
- 작업상태, 일반/긴급, 지연 여부는 별도 배지로 표현한다. ‘빨간색 = 모든 문제’처럼 다른 의미를 합치지 않는다.
- 버튼과 입력은 라벨·키보드 포커스를 제공하고 아이콘 단독 버튼에는 이름을 제공한다. 팝업은 닫힌 뒤 호출 버튼으로 포커스를 돌린다.
- 좁은 화면은 부서 카드 1열, 필터 줄바꿈, 편집 패널 전체폭으로 전환한다. 캘린더는 동일 날짜의 목록 전환을 제공하는 방식을 제안한다.
- 상태 변경·부분 업로드 결과는 화면에 남겨 사용자가 다시 확인할 수 있게 한다. 잠깐 나타났다 사라지는 알림만 사용하지 않는다.

## 9. 구현 전달 순서 제안

1. 시연 로그인·네 상위 메뉴·정비 요청·BNOC 승인/배정·공조 요청과 직접 수락·정비사 조치 완료·BNOC 종결·두 화면 갱신을 첫 상세 설계 범위로 묶는다.
2. 향후 코드 구현에서는 기본 접수·종결을 먼저 연결하고 같은 첫 기능 묶음 안에서 공조·중복 처리·권한 오류 상태를 연결한다. 공조를 후속 범위로 제외하지 않는다.
3. 부서별 병력 카드·부분 업로드와 야간 근무 취합을 설계·구현한다.
4. 통계·엑셀·계획정비·일정·운영상태·상황단계·지시·전시기 설계를 확장한다.

이는 상세화·구현 순서 제안이며 범위 축소나 현재 제품 코드 구현 지시가 아니다. 최종 구현 지시는 Planner가 UX와 기술 검토를 맞춘 후 작성한다.

## 10. Planner 조율이 필요한 사항

후속 사용자 답변으로 다음 사항은 확정되었다. 아래 기존 미정 목록보다 우선한다.

- 병력은 부서별 블록 안 계급순 세로 목록으로 표시한다. 직접 지정 상태 > 자동 오프 > 기본 주간으로 계산하고 날짜별 확인 전/완료를 별도 표시한다. 자세한 규칙은 §3.3을 따른다.
- 정비부서의 자기 부서 대시보드를 기본으로 하고 같은 대대 타 부서 정비 요약 조회를 허용한다. 타 부서 수정·병력·운영정보 조회 권한을 의미하지 않는다.
- 잘못 배정된 작업 상세에 ‘재배정 요청’과 사유 입력을 제공하고 BNOC가 정비 접수에서 담당 변경을 확정한다. 기존 작업을 복제하지 않는다. 공조는 별도 동작이다.
- 요청서 1개는 1건이다. ‘모니터 10대’ 등은 추가 메모에 적고 단일 부서 작업은 1건으로 처리한다. 업무 안내 예시는 네트워크체계팀의 랜선 고장·모니터 정비·PC 포맷이다.
- 확인은 시작과 분리한다. 작업 예정·작업 중·보류·완료를 사용하고 애매하거나 대기할 때 사유를 적어 보류한다.
- 전월 접수·당월 완료는 당월 완료 실적이다. 현재 잔량과 선택 기간 이월·신규 배정·완료·잔량의 기준을 표시한다.
- 전시기는 약 75인치 TV, 브라우저는 Edge를 우선한다. 픽셀 해상도·배율·시청 거리는 미정이다. FHD·4K는 후속 시안 비교 후보이지 확인된 출력 환경이 아니다.

근무자(야간) 화면 보완 예시:

```text
가상 A대대 / 근무 기준일
구역·직책        계급       성명         전화번호
통신일직         대위       가상A        DEMO-1001
작통일직         중위       가상B        DEMO-1002
생활관 근무자    중사       가상C        DEMO-1003
```

구역·직책별로 묶고 대대별 등록·자동 취합을 유지한다. 전화번호는 가상 내선 표시 예시이며 실제 개인정보를 사용하지 않는다. 시작·종료 일시와 근무자 소속은 상세에서 확인한다.

## 장비 운영 추가 요구사항 (2026-09-13)

정비사 전체 화면 구성은 [기준 이미지](mockup/reference-technician.png)를 따른다. 정비관리 하위에 `장비 운영`을 추가하고 부서별 장비를 등록·관리한다.

| 하위 탭 | 내용 |
|---|---|
| 장비 목록 | 순번, 부서, 망 종류(국방망·전장망·센서망·LTE망·VoIP망 등), 장비명, 사업명, 사업년도 |
| 정보보호 프로그램 | 장비별 백신 버전·설치현황, 설치 불가 사유·비고, 업체 공문 첨부 |
| 세 번째 탭 | 사용자 검토 중. 확정 전에는 메뉴를 만들지 않는다. |

두 탭은 동일한 장비 식별자를 사용한다. 목업은 부서·망 필터와 검색, 등록·수정, 공문 선택·다운로드를 제공한다. 설치현황의 세부 상태, 설치 완료 시 버전 필수, 설치 불가 시 사유 필수 및 공문 미첨부 표시, 파일 형식·10MB 제한은 검토용 구현안이다. 정비사의 타 부서 편집 범위는 아직 미정이며 실제 서비스는 허용된 부서만 서버에서 검사해야 한다. 로컬 목업의 부서 선택은 권한 구현을 의미하지 않는다. 데이터와 파일은 메모리에만 보관한다.

### 사업 공문 공유 및 다중 첨부 (2026-09-13)

- 장비는 1대당 고정 관리번호로 식별하고 백신 버전·설치현황·사유를 개별 관리한다. 동일 사업의 동일 장비 여러 대도 서로 다른 장비다.
- 공문 원본과 장비를 다대다로 연결한다. 공문 하나가 여러 장비에 적용되고, 한 장비에 여러 공문이 연결될 수 있다. 적용 범위가 다른 공문은 별도로 추가한다.
- 목업에서는 정보보호 현황 수정 안에서 여러 파일 추가, 기존 사업 공문 재사용, 적용 장비 개별 선택을 제공한다. 사업 전체·동일 장비명 빠른 선택 후 관리번호·부서·망별로 대상을 확인한다.
- 공문 연결은 대상 장비의 설치현황·사유를 일괄 수정하지 않는다. 한 장비의 연결 해제는 다른 장비의 연결과 원본을 유지한다. 신규 장비는 기존 공문을 명시적으로 연결한다.
- 목업의 사업 후보는 사업명+사업년도, 동일 장비 후보는 장비명으로 조회한다. 실제 적용 대상은 장비 ID로 고정하므로 이름 변경으로 연결이 이동하지 않는다. 실제 서비스 설계는 `사업(project_id) → 장비(equipment_id, model_id)`와 `공문(document_id) ↔ 적용 장비`를 분리해 동명 사업·모델 오연결을 방지한다.
- 파일당 10MB 제한을 모든 파일에 검사한 뒤 한 번에 반영한다. 파일·관계 모두 시연 메모리에만 보관한다.

## 날짜·날씨 카드 (2026-09-16)

- 아래 Open-Meteo 출처·예보 모델 안내와 갱신 기준은 인터넷 시연 기준이다. 실제 인트라넷 운영에서는 국방 기상체계 연동 자료의 출처·자료 유형·갱신 주기에 맞춰 안내한다.
- 날씨 카드: `제17전투비행단 · 지역 날씨` → 기온·날씨 상태 → `청주시 청원구 내수읍` → 자료 기준 시각 → 예보 모델 자료·Open-Meteo 출처 → 새로고침 버튼 순으로 배치한다.
- 최초 로딩은 `불러오는 중…`, 최초 실패는 `날씨 확인 불가`를 표시한다. 재조회 실패 시 기존 값에 `갱신 실패, 이전 자료`를 함께 표시한다. 자료가 45분 이상 오래되면 `오래된 자료`를 표시한다.
- 날짜 카드: 한국 표준시 날짜·요일·시각을 표시하고 초 단위로 갱신한다. 정적 목업에는 `기기 시간 기준`을 표시한다. 업무 일정의 시연 날짜와 구분한다.

## 정비 안내·연락처와 태그 표시 (2026-09-16)

- 정비관리의 `정비 안내·연락처` 탭은 `부서 | 담당 업무·장비 | 대표 증상 | 부대 내선` 순서다. 내선은 한 부서에 여러 개 표시하고 용도를 병기한다. 실제 연락처 제공 전에는 가상 번호를 사용한다.
- 정비 요청의 희망 부서 옆에 `담당 부서 안내`를 제공한다. 안내에서 부서를 선택하면 기존 요청 입력을 보존하며 희망 부서와 해당 부서 태그 목록을 갱신한다. 부서를 몰라도 미지정 접수가 가능하다.
- 업무 태그는 단일 선택이며 미선택 표시는 `미지정`이다. 부서 변경으로 기존 태그가 유효하지 않으면 재선택 안내를 표시하고 미지정으로 전환한다.
- BNOC 최초 배정은 주관 부서 1곳과 대표 태그 확인이다. 이후 공조 수락으로 생성되는 작업에 `공조` 배지를 자동 표시하고, 공조받은 부서의 태그를 선택한다.
- 상세 화면에서 `업무 태그: PC`와 `참여 구분: 주관`을 별도 배지로 표시한다. 접수 대표 태그는 접수 요약에, 각 작업의 태그·참여 구분은 해당 작업 행에 표시한다. 공조 작업의 태그를 바꾸어도 접수 대표 태그는 유지한다.
- 단순 공유는 열람·참고이며 작업 건수에 넣지 않는다. 별도 공유 버튼이나 공유 권한 확대를 이번 요구사항에서 추가하지 않는다.

## 상위 조회자 전용 화면 (2026-09-25)

### GPS 전파교란 대응체계 — 목업 보완 (2026-10-07)

사용자 제공 기준으로 다음 세 정보를 독립적으로 표시한다. 기존 양호·주의·불량·미수신 4단계 목업을 대체한다.

- GPS 위기 경보등급: 실제 경보와 훈련 경보를 별도 카드로 동시에 표시한다. 각각 심각 RED / 경계 ORANGE / 주의 YELLOW / 관심 BLUE의 4단계와 적용 시각을 제공한다. 감시국 수신 상태에서 경보를 자동 발령하거나 두 경보를 서로 덮어쓰지 않는다.
- 감시국: 정상 GREEN(수신 위성 5개 이상), 주의 ORANGE(4개), 경고 RED(3개 이하), 장애 GREY(장비/네트워크 장애), 기만 BLUE(오차거리 20m 초과)의 5단계를 원형 기호와 문자로 표시한다. 조건 중복 시 **장애 → 기만 → 위성 수** 순으로 판정한다. 오차거리 정확히 20m는 기만 조건에 포함하지 않는다. 자료가 없는 것을 정상이나 확인된 장애로 간주하지 않는다.
- 전파교란 탐지장비: 레이더 아이콘으로 GPS 수신 정상 BLUE / GPS 교란 탐지 RED / 장비·네트워크 장애 ORANGE의 3단계를 표시한다. 군사분계선 인근을 가정한 임의 위치에 가상 장비 A~C를 배치하며, 지도 점선은 실제 경계선이 아닌 배치 안내선이다.

전체 감시국 상태별 개소 수, 감시국·수신 단계 필터, 지도와 동기화된 목록, 선택 감시국의 위성 수·오차거리·최종 수신·상태 변경 시각과 이력을 제공한다. 필터로 결과가 없으면 이전 선택 상세를 숨긴다. 감시국 필터는 실제·훈련 경보와 탐지장비에 영향을 주지 않는다. 탐지장비는 별도의 지도/목록 선택과 상세를 제공한다. 세 정보의 색 의미가 다르므로 각각 범례와 문자 상태를 표시한다.

대시보드는 계정 소속 비행단에 연결된 감시국 상태를 표시하고 해당 감시국 상세로 연결한다. 시연 계정은 제17전투비행단→청주로 연결하며 상위 조회자의 가상 비행단 A→성거산, B→원주 연결도 동일한 감시국 데이터를 사용한다. 이 연결과 지도 위치는 시연용 예시다. 지도는 외부 지도 서비스 없이 SVG 개략도로 표시한다. 자료 기준은 2026-09-16 14:30:00 한국 시간이며, 실제 관심·훈련 경계도 고정 시연 값이다. 실제 수신 연동, 경보 입력·발령 권한, 갱신 주기와 오래된 자료 처리 방식은 후속 확정 사항이다. 현재 목업에는 실제 경보 변경 기능이나 자동 발령 기능을 추가하지 않는다.


### 정보통신 운영현황 상세화 — 목업 반영 (2026-10-03)

- 상단 카드는 현재 확인 상태, 확인 시각, 등록 장비 수, 선택 날짜의 예정 영향을 나란히 표시한다. 현재 상태는 수동 확인값이며 하위 장비 상태나 일정만으로 상위 체계 상태를 자동 변경하지 않는다.

#### 하위 구성 배치 편의

- BNOC·관리자는 하위 체계/장비의 `⠿ 이동`을 잡고 목적지 체계의 행 또는 접힌 제목에 놓아 소속을 변경한다. 이동 가능한 목적지는 점선으로, 현재 목적지는 파란 배경으로 표시한다. 최상위 체계는 드래그 이동 대상에서 제외한다.
- 드래그가 어려운 환경은 `이동` 클릭 후 `여기로 이동` 버튼을 사용한다. `＋ 하위`로 해당 체계를 상위 구성에 미리 선택한 등록 폼을 연다.
- 하위 구성 전체와 연결된 정비 대상 ID는 유지한다. 정비 영향의 체계별 집계는 새 소속을 따르며 현재 상태 확인 시각은 변경하지 않는다. 자기 자신·자손·장비 아래로의 이동, 같은 부모로 이동, 읽기 전용 계정의 이동은 거부한다. 변경은 즉시 브라우저에 저장한다.


### 운영현황 탐색·삭제 및 대시보드 보완 (2026-10-03, 이전 배치 설명 대체)

- 운영현황 기본 범위는 전체 체계이며 체계별 현재 상태·장비 수·조회일 정비 건수를 한 번에 표시한다. 개별 체계 필터도 제공한다.
- 구성 관리 / 정비 일정 탭을 분리한다. 구성 관리에는 접히는 간결한 트리와 선택 항목 상세를 좌우 배치한다. 검색은 조회 범위의 이름·관리번호/설명에 적용하고 일치 항목의 경로를 펼친다. 작은 화면은 세로 배치한다.
- 구성 상세에서 현재 대상이 선택된 정비 등록, 일정 탭에서 조회일이 입력된 정비 등록을 제공한다. 전체 체계 조회에서 등록하면 대상을 직접 선택한다. 체계 간 이동은 목적지 선택 창, 보이는 체계 간 이동은 드래그를 지원한다.
- 연결 정비 기록이 없는 말단 항목은 이름을 정확히 입력한 후 삭제한다. 기록이 있으면 운영 종료로 보존하고 기본 목록에서 숨긴다. 운영 종료 포함으로 다시 조회한다. 예정 정비가 남아 있거나 하위 항목(운영 종료 포함)이 있으면 삭제·종료를 거부하고 선행 정리를 안내한다. 종료 항목은 이동·수정·새 예정 정비 대상에서 제외한다.
- 부서 표시명을 네트워크체계반 / 무선체계반 / 정보체계반 / 사이버 통제실로 통일한다. 기존 transmission 식별자의 표시명은 정보체계반으로 변경하며 담당 업무·권한·체계 종류를 자동 재분류하지 않는다. 이전 저장 자료의 부서명도 로드 시 변환한다.
- 대시보드 지휘서신·지시사항은 게시 자료를 사용한다. 예방정비와 일일 병력 입력 안내는 별도 업무 안내 카드에 표시하고 해당 화면으로 연결한다. 기존 고정 예방정비 지시 문구는 제거한다.
- 상위 조회자의 비행단 선택 후 운영현황에 체계별 하위 구성·장비·관리번호·위치·현재 상태·예정 정비/예상 영향을 읽기 전용으로 제공한다. 예상 영향 날짜와 정비 실적 조회 기간은 별도다. 비행단별 독립 가상 자료이며 BNOC 저장 자료와 서버 동기화되지 않는다.
- 검증: 관련 모델 31개 통과. 운영현황 브라우저 시나리오에서 검색, 문맥별 정비 등록, 삭제/운영 종료와 재조회, 저장 유지, 계층 이동, 업무 안내 분리, 비행단 상세, 읽기 전용, 모바일 너비를 확인했다.


### 일일 통합 및 기간별 엑셀 다운로드
- 병력·근무자(야간)는 한 기준일로 묶어 XLSX의 별도 시트로 내보낸다. 일일 통합에는 현재 운영현황과 기준일 정비 예정 영향도 포함한다. 당일 정비 실적은 해당 조회 권한이 있고 시연 기준일 이하일 때 포함한다.
- 기간별 정비 현황은 조회 적용된 시작일/종료일/부서 또는 비행단 범위로 별도 파일을 만든다. 변경 중인 조회 조건은 먼저 적용하도록 안내한다. 그래프 상세 선택은 집계 전체와 구분하여 적용하지 않는다.
- 현재 화면에서 허용하는 데이터 범위를 따른다. 상위 조회자에게 병력·근무 자료를 추가 공개하지 않으며 비행단별 독립 운영자료만 일일 다운로드한다. 서버 권한 검증은 후속 구현이다.
- 파일 상단에 날짜/기간·범위·추출 시각·계정·시연 자료 여부·상태 기준을 표시한다. 날짜는 엑셀 날짜형, 건수는 숫자형, 사용자 문자열은 수식이 아닌 텍스트로 기록한다. 필터와 상단 고정행을 제공한다.
- 근무자는 선택 날짜에 시작하는 저장 편성 기준이며 자정 이후 종료시각을 유지한다. 미등록일은 빈 명단과 미등록 안내를 제공한다. 운영상태·구성과 병력 명단/계급/소속은 현재 정보이며 과거 스냅샷으로 표시하지 않는다.


### 확정한 범위 조정

- 일반 사용자의 병력 현황 메뉴·조회·일일 엑셀 병력 시트를 제외한다. 근무자(야간) 조회 및 해당 시트 내보내기는 유지한다. 일반 사용자에게 병력 입력 업무 안내를 표시하지 않는다.
- 장비 운영 표시명을 장비 관리로 통일한다. 기존 장비 식별자·저장 자료는 유지한다.
- 모바일 지원은 제외한다. PC 최소 1280px 및 전시기 중심으로 설계하며 기존 모바일 배치·모바일 폭 회귀 조건은 최신 수용 기준에서 제외한다.
- 대리 접수 추가, 16시 보고 제외·엑셀 유지, 정비사의 부대 전체 병력 조회로 확정했다. 아래 최신 확정 사항을 따른다.

## 목업 검토 후 확정 사항 (2026-10-03)

이 절은 앞선 모바일 지원·독립 시연 자료·미연동·결정 대기 설명보다 우선한다. 적용 대상은 docs/design/mockup.html 통합 목업이며 서버 구현 완료를 뜻하지 않는다.

- 일반 사용자는 병력 메뉴·조회·병력 엑셀 시트를 사용할 수 없고 근무자(야간)는 조회·내보내기 가능하다. 정비사는 부대 전체 병력을 조회하며 수정은 BNOC·관리자 권한이다.
- 장비 운영 명칭은 장비 관리로 변경했다. PC 최소 1280px와 전시기만 지원하며 모바일 화면 및 모바일 수용 조건은 제외한다.
- BNOC·관리자의 대리 접수를 추가했다. 실제 요청 부서와 접수 계정을 구분한다. 16시 보고 보관 기능과 준비 중 버튼은 제외하고 날짜별·기간별 엑셀만 유지한다.
- 정비사는 미확인 배정·공조·오늘 작업·보류 작업을, 일반 사용자는 내 요청·근무자·담당 부서를 먼저 본다. 엑셀 도구와 CPCON 전체 설명은 펼쳐서 사용한다.
- 새 운영 정비 일정은 담당 부서의 계획정비 작업을 생성하거나 기존 작업 하나에 연결한다. 작업 완료는 일정에 반영되며 양쪽 상세에서 이동할 수 있다. 기존 요청에 연결한 영향 일정의 취소는 원래 정비 요청을 취소하지 않는다. 자동 생성된 계획정비 작업만 일정 취소에 따라 집계에서 제외한다.
- 운영 구성의 장비는 장비 관리의 등록 자료를 연결한다. 기존 가상 구성 장비는 최초 실행 시 장비 목록으로 이관한다. 구성에서 삭제해도 장비 관리 원장은 유지하며 정비 기록이 있는 구성은 운영 종료로 보존한다.
- 제17비행단의 상위 조회 화면과 엑셀은 동일 브라우저에 저장한 BNOC 자료를 참조한다. 가상 비행단 A·B는 독립 예시 자료다. 여러 사용자·PC 사이의 동기화는 서버 구현 범위다.
- 신규 요청은 BNOC, 배정·재배정은 담당 부서, 공조 요청은 수신 부서, 작업 완료는 BNOC 알림으로 연결한다. 알림 읽음은 작업 확인과 별개다. 개인 정비사 지정은 현재 부서 단위 배정 범위를 확장하지 않는다.
- 지시사항은 제목·본문 직접 입력 및 게시 전 검토 방식이다. 자동 문서 분석이나 자동 요약으로 표시하지 않는다. 실제 날짜와 가상 업무 기준일을 구분하고 미등록 과거 근무 편성을 임의로 만들지 않는다.
