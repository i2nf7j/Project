# 일일 정비 실적·대조 업무 기준 재정리

기준일: 2026-10-07. 사용자 전달사항과 아래 인용 문구를 바탕으로 작성한 보완안이다. 대회 요구 문서 전체와 DELLIS의 실제 입력 항목·집계 규칙은 확인하지 않았다. 아래 ‘제안’과 ‘확인 필요’를 확정 요구나 구현 완료로 해석하지 않는다.

추가 전달 문구: “작업 완료 시 조치결과 직접 수정 및 매일 16시 기준 DELLIS 현황과 정비완료 현황 확인/일치화”. 사용자는 작업건수 입력 주체를 정비통제담당이 아닌 **정비부서**로 정정했다. 앞서 제시한 ‘정비통제담당이 DELLIS 수치를 직접 입력’ 방식은 선택·확정되지 않은 제안이므로 구현 기준에서 제외한다.

## 1. 다시 잡을 시스템 목적

**권장 방향: 정비부서가 작업건수와 조치결과를 직접 관리하고, 매일 16시 기준으로 DELLIS 현황과 정비완료 현황을 확인·일치화하는 업무를 지원하는 체계.** BNOC 정비통제담당의 취합·점검 역할과 최종 확인 권한은 별도로 정한다.

DELLIS를 대체하거나 기존 자료 전체를 이관하는 사업으로 확장하지 않는다. 실제 외부 API 연동·자동 입력을 전제로 설계하지 않는다. 정비 요청부터 완료까지의 업무 기록과 외부 기준값을 비교하는 기능을 구분한다. 무엇을 기준으로 대조하고 어느 체계에서 정정하는지는 담당 업무 확인 후 확정한다.

## 2. 전달사항과 확정 수준

| 항목 | 현재 이해 | 상태 |
|---|---|---|
| 08:30 일일 작업건수 | 작업건수 입력 주체는 정비부서. 계획·전일 실적·당일 미완료 대상 중 무엇인지 불명확 | 주체는 사용자 정정 반영. 입력값의 의미는 확인 항목으로 유지 |
| 완료 시 조치결과 | 정비부서가 완료 처리 시 조치결과를 직접 작성 | 사용자 답변으로 의미 확인. 완료 후 정정 기능을 요구한 것이 아님 |
| 16:00 대조 | 부서별 정비 완료 건수만 대조. 기간은 전일 16:00~당일 16:00을 잠정 기준으로 사용 | 수준은 확인, 기간은 사용자 답변 ‘2번 같기는 해. 일단은’에 따른 가정이며 확정 아님. 집계 단위 추가 확인 |
| 담당 직책 | BNOC 내 정비통제담당과 실적 입력 주체인 정비부서를 구분 | 통제담당의 취합·점검·최종 확인 권한은 추가 확인 |
| 지휘관·참모 / 작전 관련 요청 | 요청 시 성격과 긴급성을 식별할 기능을 보완할 필요 | 신규 요구, 입력·확정 방식은 제안 단계 |
| 기존 체계 이관 | 전체 이관 대신 업무 기준을 다시 정리 | 사용자 방향 반영 |

## 3. 08:30 입력은 의미부터 확인

작업건수는 정비부서가 입력한다. 입력 주체가 확인되어도 입력 시각만으로 실적의 대상 날짜와 집계 단위를 정할 수는 없다. 08:30의 의미는 기존 답변대로 확인 항목으로 유지한다.

| 가능한 의미 | 필요한 값 | 주의점 |
|---|---|---|
| 오늘 수행할 계획 | 대상일, 부서, 계획 건수 | 계획 건수를 완료 실적으로 합산하지 않음 |
| 전날 수행·완료한 실적 | 실적 대상일, 부서, 실적 건수 | 입력한 오늘 날짜와 실적 날짜를 분리 |
| 당일 관리대상·미완료 현황 | 기준시각, 이월·신규·미완료 건수 | 매일 같은 이월 작업을 신규 건수로 중복 계산하지 않음 |

먼저 ‘어떤 화면에 어떤 날짜의 어떤 건수를 입력하는가’를 확인한다. 이 체계에서 이미 상세 등록한 작업을 집계해 확인하는 것인지, 외부 자료의 숫자를 수기로 입력하는 것인지도 구분해야 한다. 확정 전에는 입력 폼이나 08:30 자동 마감·알림을 구현하지 않는다.

## 4. 16:00 부서별 완료 건수 대조

사용자 답변으로 대조 수준은 **부서별 정비 완료 건수만 비교**하는 것으로 정했다. DELLIS의 개별 정비 내역을 가져오거나 일대일로 연결하는 기능은 이번 대조 범위에 넣지 않는다. 아래 입력 방법과 기록·확정 방식은 아직 설계 제안이다.

화면 후보: `부서 | 우리 체계 완료 | 16시 대조 확인 상태 | 차이 사유 | 확인자·시각`. DELLIS 숫자를 이 체계에 별도로 입력하도록 요구하는지는 아직 확인되지 않았다. 숫자 입력을 채택할 경우에만 `DELLIS 완료 | 차이(우리−DELLIS)`를 추가하며 미입력은 0건과 구분한다. 숫자 일치는 ‘건수 일치’로 표시하고 개별 정비 내용까지 일치했다고 표현하지 않는다.

### 비교 기준

- 비교 전에 대상 날짜·기간, 부대·부서 범위, 건수 단위, 완료 정의를 맞춘다. 우리 체계의 접수 1건과 공조 포함 작업 3건은 다른 숫자다. DELLIS의 ‘정비 현황’ 총수를 우리 ‘완료 작업’ 수와 바로 비교하지 않는다.
- 일일 대조 기간은 **전일 16:00~당일 16:00(한국 표준시)**을 잠정 기준으로 둔다. 사용자 답변은 추정이므로 대회 요구로 확정하지 않는다. 예를 들어 10월 7일 대조는 10월 6일 16시~10월 7일 16시 완료분을 대상으로 하고, 10월 7일 16시 이후 완료분은 다음 대조 기간으로 넘기는 안이다.
- 정확히 16:00에 완료된 작업이 두 번 집계되지 않도록 `전일 16:00 초과, 당일 16:00 이하` 경계를 제안한다. 이 경계 규칙과 휴일·누락 입력 처리는 아직 확정하지 않았다. 08:30 입력값의 의미와도 별개다.
- 현재 목업은 작업 완료일을 날짜 단위로 저장하므로 16시 경계 집계를 검증할 수 없다. 구현 시 실제 완료 시각과 시간대 기준을 마련해야 한다. 기존 날짜별·기간별 통계의 기간을 이 잠정 대조 기간으로 일괄 변경하지 않는다.
- 우리 체계의 ‘부서 조치 완료’와 ‘BNOC 최종 종결’을 구분한다. DELLIS의 어느 상태와 대조할지 확인한 후 대응시킨다.

### 집계 기준 시각과 접수·조치 시간의 구분

16시는 완료 실적의 대조 기준이며 접수 종료 시각을 뜻하지 않는다. 16시 이후 요청의 등록을 막는 규칙은 도입하지 않는다. 요청 등록 가능 여부와 실제 담당자의 근무·당직 시간, 긴급 조치 대응 기준은 별개다. 접수가 가능하다고 상시 즉시 조치를 약속하는 것도 아니다.

사용자의 ‘당일 00:00~16:00이면 이후 정비는 받지 않는 것인가’라는 질문은 기간 변경 지시로 해석하지 않고 기존 전일 16시~당일 16시 잠정 기준을 유지한다. 매일 00:00~16:00만 집계하면 16시~24시 완료분을 별도로 반영하지 않는 한 누락이 생긴다. 현재 잠정안에서는 16시 이후 완료분은 다음 대조 기간에 포함한다. 요청 접수일이 아니라 실제 완료 시각으로 완료 실적의 귀속을 판단한다.

### 첫 구현 후보

1. 정비부서가 자기 부서의 작업건수·작업 상태·조치결과를 관리한다.
2. 우리 체계는 해당 기준에 맞는 완료 실적과 근거 작업 목록을 계산한다.
3. 정비부서가 16시 기준 DELLIS 현황과 자기 부서 완료 건수를 확인·일치화하는 흐름으로 해석한다. 대조 수행 주체와 BNOC 최종 확인 여부는 업무 분장을 추가 확인한다. DELLIS 수치의 별도 입력·업로드·자동 연동은 필수 기능으로 가정하지 않는다.
4. 대조 확인 상태·차이 사유·확인자를 기록하는 방식을 제안한다. 외부 숫자 입력을 채택하더라도 양쪽 숫자를 합산해 총실적으로 만들지 않는다.
5. 누락·중복·기준 차이를 확인한 뒤 필요한 체계의 원자료를 정정하고 다시 대조한다. 숫자를 맞추기 위해 우리 작업을 임의로 완료 처리하지 않는다.

예: 동일 기준으로 우리 완료 12건, 외부 기준 10건이면 ‘차이 +2, 확인 필요’로 표시한다. 숫자가 같아도 개별 작업의 동일성을 증명하지는 않으며 이번 기능의 완료 수준은 부서별 건수 대조다.

대조 기록을 도입한다면 기준·확인자·확인 상태·차이 사유를 남기고, 외부 숫자를 입력받는 경우에는 그 값도 보존하는 방식을 제안한다. 대조 기록 수정 방식과 확정 권한은 별도 결정한다. 기존에 제외한 ‘16시 자동 보고서 생성·수정/복원 기능’을 통째로 복원하는 결정은 아니다.

### 조치결과 수정의 경계

사용자 답변으로 **완료 처리 시 조치결과를 직접 작성하는 의미**라고 확인했다. 현재 목업은 완료 시 결과 입력을 요구하고 완료 후 수정은 차단하므로 이 부분은 기존 흐름을 유지한다. 이번 요구로 완료 후 정정·작업 재개·완료일/건수 변경 권한을 추가하지 않는다.

## 5. BNOC와 정비통제담당 구분

BNOC는 조직/업무 영역, 정비통제담당은 담당 직책으로 구분한다. 작업건수·조치결과 입력은 정비부서가 수행하며 정비통제담당에게 일괄 입력 책임을 배정하지 않는다. 기존 bnoc 시연 역할을 실제 사용자 식별자로 사용하지 않는다.

정비통제담당의 후보 업무는 기존 접수·배정 통제, 부서별 실적·미입력·대조 미확인 현황의 취합·점검이다. 08:30 작업건수 입력이나 DELLIS 수치 입력을 담당 직책의 확정 업무로 두지 않는다. 최종 확인·정정 권한도 추가 확인하며 관리자·정비부서·상위 조회자의 기존 권한을 직책 명칭만으로 확대하지 않는다.

## 6. 요청 성격과 긴급성 보완안

기존 부서별 업무 태그(PC·네트워크 등)는 유지하고 아래 정보를 별도로 둔다.

**2026-10-07 사용자 선택 1번:** 요청자가 긴급 사유를 입력하여 긴급 요청으로 표시하고 정비통제담당이 확인한다. 요청 성격과 긴급도를 구분한다. 구체적인 확인·변경 이력, 필요 시각 입력, 표시·알림 UI는 아래 설계안으로 상세화한다.

| 구분 | 입력 후보 | 의미 |
|---|---|---|
| 요청 성격 | 지휘관 요청 / 참모 요청 / 작전 관련, 복수 선택 가능 | 요청의 배경. 선택했다고 자동으로 긴급이 되지는 않음 |
| 요청 긴급도 | 일반 / 긴급 | 요청자가 표시하고 정비통제담당이 확인하는 방식으로 확정 |
| 긴급 사유 | 긴급 선택 시 필수 | 요청자가 긴급으로 요청한 근거를 직접 입력 |
| 필요 시각 | 필요한 경우 입력 | 요청자가 원하는 시각이며 이행 약속과 구분 |
| 통제 확인 | 정비통제담당의 확인·변경 이력 | 요청자가 표시한 긴급도와 담당자가 확인한 우선순위를 구분 |

화면에는 요청 성격과 긴급 배지를 구분해 표시하고 긴급 목록·알림에서 놓치지 않게 한다. 긴급 요청은 08:30 입력이나 16:00 대조 시간까지 기다리지 않고 기존 접수·배정 흐름으로 전달하는 방향을 제안한다.

‘지휘관·참모 요청’은 요청의 성격이며 로그인 역할이 아니다. 현재 읽기 전용인 상위 조회자에게 요청 생성·수정 권한을 자동 부여하지 않는다. 기존 요청 생성 권한이 있는 사용자가 긴급 사유와 함께 표시하고 정비통제담당이 확인한다. BNOC 대리 접수에도 동일한 요청 정보를 담는 방향이며 세부 확인 화면은 아직 구현하지 않았다.

## 7. 기존 결정에 미치는 영향과 다음 순서

- 2026-10-03의 16시 보고 제외와 이후 08:30 별도 기록 제외는 이번 요구와 충돌할 수 있으므로 관련 집계·보고 기준을 재검토 상태로 전환한다. 기존 코드에 16시 보고를 바로 복원하거나 완료 집계를 임의로 바꾸지 않는다.
